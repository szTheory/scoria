## Known Duplication Or Legacy Candidates

- `metric/1`, `overview_stats/1`, and `signal_strip/1` overlap. `overview_stats/1` is the likely canonical page-level summary; `metric/1` may remain a low-level internal building block; `signal_strip/1` should be evaluated for migration or explicit deprecation.
- Some pages still contain direct `scoria-panel` markup or page-local panel composition. These should be audited against `page_section/1` and `panel/1` conventions rather than patched ad hoc.
- Review Queue still uses mixed filter/panel markup and should be audited for the same scan-surface conventions as Approvals, Incidents, and Datasets.
- Evidence notebook adapters remain intentionally thin, but Phase 39 should verify their output is operator-oriented and not a backend evidence dump.
- Tables have strong responsive primitives, but each page still needs a JTBD check to decide whether a table or list/card scan is the right shape.

## Accessibility And Motion Risk Register

High-priority checks:

- Drawer and modal focus trap/restoration after LiveView patches.
- Escape and click-outside dismissal consistency across drawer, modal, command palette, and mobile nav.
- Icon-only buttons have durable accessible names and target sizes at all sizes.
- Raw evidence copy control announces copied/unavailable states without relying only on icon change.
- Toasts are readable over dense UI and do not obscure primary decision controls.
- Tables with horizontal scroll expose focus outlines and mobile summaries where needed.
- Empty states do not look hoverable/clickable unless they contain a real action.
- `prefers-reduced-motion` disables nonessential motion across overlays, mobile nav, command palette, skeletons, and page transitions.
- Status, severity, selection, and sort state are not color-only.

Existing support:

- `assets/js/scoria.js` already has focus helpers for command palette and mobile nav.
- `assets/css/05-motion.css` already defines restrained motion and reduced-motion collapse.
- `assets/css/04-components.css` includes layer comments and focus-outline accommodations for drawers and tables.
- Component tests already assert drawer/modal accessible names and table `aria-sort`.

## External Design Lessons Applied

- Phoenix/LiveView favors function components with explicit attrs/slots for reusable visual surfaces; reserve LiveComponents for stateful reuse.
- Phoenix.LiveView.JS and small hooks are appropriate for patch-aware show/hide/focus/copy behavior; avoid large client-side widget stacks.
- GOV.UK-style IA guidance supports orienting by user need and next action, not implementation structure.
- WAI-ARIA APG guidance supports native controls first and full keyboard/screen-reader behavior when custom widgets are unavoidable.
- Carbon-style semantic tokens fit Scoria's current token strategy: separate palette from role.
- Polaris-style empty states fit Scoria's operator tone when they are specific, action-guiding, and not cute.
- Motion should communicate state and spatial relationship; Scoria should keep it restrained, fast, and reduced-motion-safe.
