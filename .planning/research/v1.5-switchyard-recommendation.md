# v1.5 Switchyard Recommendation

**Date:** 2026-05-17
**Status:** Active milestone recommendation

## Summary

The coherent shape for `v1.5 Switchyard` is remote MCP connector productization for embedded Phoenix apps, not a connector marketplace and not a hosted agent platform.

Recommended milestone defaults:

- real remote connector support, not metadata-only scaffolding
- stateless-first invocation by default
- stateful remote session lifecycle only as an opt-in connector capability
- operator/audit visibility as the primary user-facing outcome
- governance and approvals as the second-order UX priority
- curated connector profiles, not a marketplace
- browser/code-exec explicitly out of scope for this milestone

## Why This Fits Scoria

- Preserves the embedded Phoenix product boundary.
- Reuses Scoria's durable approval, workflow, telemetry, and evidence substrate instead of bypassing it.
- Extends Keystone's clarified identity/runtime/install surface into remote tool connectivity before taking on release-ops or future-bet runtime expansion.

## Key Recommendations

### Product Shape

- Keep MCP protocol traffic in Plug-facing boundaries.
- Keep LiveView focused on operator UX only.
- Keep host apps responsible for principal resolution and business authorization.
- Keep Scoria responsible for connector policy, approval, evidence, and boring defaults.

### Technical Defaults

- Encrypted DB-backed credential storage
- Boring connector discovery and capability refresh defaults
- Least-privilege scopes
- Approval on remote write / exec / scope escalation paths
- Low-cardinality telemetry plus exact durable evidence refs

### Risks To Avoid

- Hosted connector broker drift
- Browser/code-exec expansion in the same milestone
- Treating remote connector session IDs as Scoria run truth
- Storing long-lived connector secrets in Plug session cookies
- Letting LiveView mutate approval state directly
