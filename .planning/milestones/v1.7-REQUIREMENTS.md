# Requirements: v1.7 Outrider

## Overview

The `v1.7 Outrider` milestone extends Scoria's reach by introducing out-of-process multi-runtime integration capabilities (using the Model Context Protocol, or MCP) and an asynchronous memory compaction engine. This allows Scoria to act as an orchestration or observability layer for external runtimes (like Python or Node.js) and handle long-running session state efficiently without bloating context windows—all while strictly adhering to its embedded Phoenix-native architecture and Ecto/Oban operational primitives.

## Scope

- **In Scope:** 
  - Implementation of Model Context Protocol (MCP) over HTTP/SSE via standard Phoenix Plugs.
  - Tracking external agent runtime health using Phoenix Presence.
  - Asynchronous memory/session compaction pipeline using Oban and Ecto.
  - LiveView operator UX for observing compacted memory states and external runtime telemetry.
- **Out of Scope:** 
  - In-process execution of Python/JS (no NIFs for foreign runtimes).
  - Use of the Ash framework (strictly pure Ecto and Phoenix).
  - Synchronous LLM calls for memory compaction within the web request lifecycle.
  - Vector DB semantic RAG injection (deferred until the basic summarization pipeline is stabilized).

## Core Requirements

### OUTRIDER-01: MCP Server-Sent Events (SSE) Boundary
Scoria must expose an HTTP/SSE boundary that implements the Model Context Protocol (MCP) Server specification to enable external runtimes to connect, discover, and invoke tools managed by Scoria.

### OUTRIDER-02: External Agent Presence Tracking
Scoria must utilize Phoenix Presence to track the health, liveliness, and connection state of external agents attached via the MCP boundary, allowing operators to detect silent disconnects or stalled runtimes.

### OUTRIDER-03: Asynchronous Memory Compaction Worker
Scoria must provide an Oban-backed worker pipeline that asynchronously summarizes older raw runtime events into a compacted format to prevent context token exhaustion without blocking BEAM schedulers.

### OUTRIDER-04: Memory Archival and Ecto Schema Updates
Scoria must implement Ecto schema updates to support `compacted_memories` and manage the lifecycle of original `runtime_events` (e.g., soft-deletion or archival) after successful compaction.

### OUTRIDER-05: Compaction Trigger Mechanisms
Scoria must implement configurable heuristics (e.g., a token-based sliding window or time-based inactivity) to trigger the enqueueing of compaction jobs for active sessions.

### OUTRIDER-06: Operator UX for Memory Time-Travel
Scoria's LiveView dashboard must be updated to allow operators to inspect both the raw archived events and the resulting compacted summaries, clearly diffing what the external agent "remembered" versus what actually occurred.

### OUTRIDER-07: Operator UX for External Runtimes
Scoria's LiveView dashboard must provide real-time visibility into the external runtimes connected via Phoenix Presence, displaying their status, identity, and active session linkages.
