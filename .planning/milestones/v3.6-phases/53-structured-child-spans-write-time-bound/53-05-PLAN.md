Purpose: SC#1 (`tool` as a real child span), SC#3 (failure-bearing), SEC-01 (fingerprint never args).

    `handle_event/4` clauses:
    - `[:scoria, :tool, :started]` -> `:ok`. No span. A span needs a duration and there is none yet; the terminal events carry `%{duration: duration}`.
    - `[:scoria, :tool, :completed]` -> a terminal span with `status: "completed"`, `status_code: "OK"`.
    - `[:scoria, :tool, :timeout]` -> `status: "timeout"`, `status_code: "ERROR"`.
    - `[:scoria, :tool, :failed]` -> `status: "failed"`, `status_code: "ERROR"`.

    A shared private `emit_tool_span(status, status_code, measurements, metadata)` builds all three terminal spans.

    **PROJECT the metadata; never merge it (D-04b).** `Scoria.MCP.Executor` merges the raw tool argument values into the metadata (`executor.ex:37`) and puts a raw failure term on the `:failed` event (`:63`, `:69`). The adapter reads exactly five fields into attributes and reads nothing else:
    - `"tool_ref"` — `metadata[:tool_ref]` (the executor already sets it via `Map.put_new(:tool_ref, inspect(tool_module))` at `:39`)
    - `"tool_name"` — derived from the tool module (a module name is low-cardinality and enum-like)
    - `"status"` — the closed value `"completed"` / `"timeout"` / `"failed"`
    - `"duration_ms"` — `System.convert_time_unit(measurements[:duration], :native, :millisecond)`
    - `"args_fingerprint"` — `Integer.to_string(:erlang.phash2(metadata[:args]))`. Fingerprint, never args. This is already the house rule: `lib/scoria/sre/audit_outbox_event.ex:32` has an `args_fingerprint` column and no `args` column, and `executor.ex:228` already computes exactly this hash for budget reservation.

    The failure term (`metadata[:reason]`) is NEVER read into an attribute. It is an arbitrary Elixir term that can embed anything the tool touched. The `status` enum is the entire failure vocabulary this span carries.

    Then the standard pipeline every span in this phase shares:
    - `span_kind` = `SpanKind.normalize("mcp")`; `attributes[Semconv.openinference_span_kind_key()]` = `SpanKind.to_openinference(span_kind)` (`"TOOL"` — the one non-1:1 kind translation).
    - `Semconv.merge_host_declared/2` over the metadata (the four ATTR-01 keys).
    - `tenant_id` / `workflow_run_id` / `session_id` written BOTH top-level on the span map AND into `attributes` (D-00c/D-01e — without the top-level `tenant_id` the broadcast fail-closes; without the attributes copy the dashboard cannot hydrate it).
    - `trace_id` = `metadata[:trace_id]`, `parent_id` = `metadata[:parent_id]` — explicit only (D-02a). Plan 53-08 threads both into the MCP call context from the workflow runtime. If `trace_id` is absent, fall back to a freshly-minted id but note in the moduledoc that this produces an ORPHAN trace and is a last resort, not the intended path.
    - `id` = a freshly-minted `Ecto.UUID.generate()` — the span's OWN id. A flush-time id (via `Buffer`'s `put_new_lazy`) is unreferenceable as a future `parent_id`.
    - `start_time` back-dated from the duration (`DateTime.add(now, -duration_ms, :millisecond)`), `end_time` = now. This gives the span a REAL duration in the trace tree rather than a zero-width bar.
    - Emit on `[:scoria, :observe, :span, :stop]`, wrapped `try/rescue -> :ok` (the shared loud-but-non-fatal rule — observability never breaks host business logic).

    **Attach on boot.** In `lib/scoria/application.ex`, call `Scoria.Observe.Adapters.MCP.attach()` inside the same `maybe_observe_buffer/0` helper plan 53-01 added, right after `Scoria.Observe.Telemetry.attach()`. Match-and-ignore `{:error, :already_exists}` identically. Gate it on the same `config :scoria, Scoria.Observe, enabled:` key — one switch turns the whole observe pipeline on or off.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| `Scoria.MCP.Executor`'s telemetry metadata -> `Adapters.MCP` | This metadata map contains RAW tool argument values (`executor.ex:37`) and, on failure, a RAW error term (`:63`, `:69`). It is the single richest source of untrusted, potentially PII- and prompt-bearing data in the observe pipeline. |
| `Adapters.MCP` -> `[:scoria, :observe, :span, :stop]` -> Postgres | Whatever this adapter projects becomes durable and multi-tenant-readable. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-53-01 | Information Disclosure | `Adapters.MCP` attribute projection | critical | mitigate | PROJECT five named fields; never `Map.merge` the metadata. Tool arguments are represented ONLY by `args_fingerprint` (`:erlang.phash2`) — the house rule `Scoria.SRE.AuditOutboxEvent` already follows (an `args_fingerprint` column, no `args` column). Test 5 asserts a distinctive token from the raw args is absent from the encoded persisted attributes. `Bounds` (53-04) is the backstop, not the primary defense — a projection that never reads the field cannot leak it. |
| T-53-05 | Information Disclosure | the `:failed` event's raw `:reason` term | high | mitigate | The failure term is never read into an attribute. An arbitrary Elixir term can embed anything the tool touched — a query, a parameter map, a response body. The closed `status` enum (`completed`/`timeout`/`failed`) is the entire failure vocabulary this span carries. Test 6 asserts a distinctive token from the failure term is absent from the encoded attributes. |
| T-53-04 | Information Disclosure / Spoofing | `tenant_id` double-write | high | mitigate | The span writes `tenant_id` top-level (so `ReviewerBroadcast` routes to the correct tenant topic instead of fail-closing) and into `attributes` (so `OrchestratorLive` can hydrate it). Test 8. |
| T-53-15 | Spoofing | orphan `trace_id` fallback | medium | accept | If a host calls the MCP executor with no `trace_id` in context, the adapter mints one and the span lands in a single-span orphan trace. This is a visibility loss, not a security failure — no cross-trace contamination is possible because the minted id is fresh. Documented in the moduledoc as a last-resort path; plan 53-08 threads the real `trace_id` on the workflow path. |
| T-53-12 | Tampering (host behavior altered by observability) | the emit wrap | high | mitigate | The emit is wrapped `try/rescue -> :ok`. A passive telemetry listener must never be able to fail a host's tool call. `test/scoria/mcp/` staying green is an explicit acceptance criterion. |
| T-53-SC | Tampering | npm/pip/cargo/hex installs | high | accept | No package-manager installs in this phase (53-RESEARCH.md § Package Legitimacy Audit). |
</threat_model>
