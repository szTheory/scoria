<objective>
Create the `Scoria.Observe` public facade with two symmetric host-facing emitters — `emit_retriever_span/1` (D-R7, the RETR-01 spine) and `emit_prompt_span/1` (D-ATTR01-7 resolution, the ATTR-02 lane). Both build a span map and emit `:telemetry.execute([:scoria, :observe, :span, :stop], %{}, span)`, reusing the Phase-51 redaction + `ReviewerBroadcast` + FK-safe `Buffer` flush verbatim (RESEARCH Recommendation 1). This is the doctrine-honest injection seam: req_llm cannot forward host metadata (verified — RESEARCH §8b), so the host calls these Scoria-owned helpers.

Purpose: Retrieval becomes visible in the trace tree as a linked RETRIEVER span; prompt composition attributes reach a Scoria-emitted span. Both keep `knowledge.ex`/host code free of span plumbing (consumer-not-provider DNA).
Output: `lib/scoria/observe.ex` with two `:ok`-returning emitters; a no-DB unit test attaching a telemetry handler to capture and assert each emitted span map.

## Boundary note (SC#4 reinterpretation — state in SUMMARY)
`emit_prompt_span/1` carries ATTR-02 composition **attributes** on a Scoria-emitted composition span. It does NOT build a real duration/parent-linked PROMPT child span, `ai_span_events`, or the SEC-01 write-time bound — those are Phase 53 / EVENT-01. ROADMAP SC#4 says "PROMPT span"; in Phase 52 the identical Semconv keys ride the composition span and relocate onto a real PROMPT child span in Phase 53 with zero contract change (D-ATTR02-1).
