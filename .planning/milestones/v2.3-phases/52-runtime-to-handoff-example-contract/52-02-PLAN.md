<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Phoenix controller/session -> Scoria facade | Untrusted host request/session data is normalized into identity and explicit runtime/handoff inputs. |
| Host escalation code -> Scoria.start_handoff_run/3 | Host policy decision and projected context enter Scoria as explicit opts. |
| Runtime persistence -> Scoria.get_run_detail/1 | Durable runtime state is exposed through curated DTOs, not raw tables. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-52-01 | Information Disclosure | `projected_context` examples and tests | mitigate | Add DB-backed tests for accepted `%{"task" => "policy-and-accuracy review", "draft_answer" => draft_answer}` and rejected `%{"session" => ...}` projected context; docs must avoid broad state transfer. |
| T-52-02 | Elevation of Privilege | host-owned escalation branch | mitigate | Require docs to say `The host app owns this escalation decision. Scoria only receives the explicit handoff contract you pass to \`Scoria.start_handoff_run/3\`.` |
| T-52-03 | Spoofing / Repudiation | `session_id` versus `run_id` | mitigate | Tests and docs must assert `started.run_id != handoff_run.run_id` and state `session_id groups related host turns; run_id names one exact Scoria execution.` |
| T-52-04 | Information Disclosure | delegated readback | mitigate | Docs and tests must inspect delegated evidence through `Scoria.get_run_detail(handoff_run.run_id)`; acceptance criteria prohibit `Scoria.Workflows` in the Phoenix guide. |
</threat_model>
