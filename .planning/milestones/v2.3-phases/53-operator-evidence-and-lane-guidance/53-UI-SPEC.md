## Typography

Use exactly these four text roles in Phase 53 UI changes:

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 14px | 400 | 1.5 |
| Label | 12px | 600 | 1.5 |
| Heading | 18px | 600 | 1.2 |
| Display | 30px | 600 | 1.2 |

Constraints:

- Use only weights `400` and `600`.
- Use uppercase tracking only for compact evidence labels, matching existing `text-xs uppercase tracking-[0.16em]` to `tracking-[0.24em]`.
- Use monospace only for IDs, API names, role IDs, status values, and projected-context keys.
- Do not add hero-scale text, marketing headings, or explanatory page banners.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#fafaf9` (`stone-50`) | Workflow page background and neutral evidence panel fields |
| Secondary (30%) | `#ffffff` | Main cards, evidence cards, detail cards, details disclosure panels |
| Accent (10%) | `#1d4ed8` (`blue-700`) | `Inspect Delegated Evidence` anchor, operator evidence links, existing primary action text states |
| Destructive | `#be123c` (`rose-700`) | Failed delegated status and destructive/error states only |

Accent reserved for: `Inspect Delegated Evidence`, links to operator evidence or trace/run anchors, existing enabled primary buttons, and informational blue evidence bands already present on the workflow page. Do not use accent for every badge, every card border, or normal static labels.

Semantic status colors:

- `completed`: emerald badge (`emerald-100` background, `emerald-700` text).
- `running`: sky badge (`sky-100` background, `sky-700` text).
- `waiting_for_approval`: amber badge (`amber-100` background, `amber-800` text).
- `failed`: rose badge (`rose-100` background, `rose-800` text).
- `child_step_pending` or unknown: stone badge (`stone-200` background, `stone-700` text).

## Interaction Contract

| Surface | Contract |
|---------|----------|
| Stable anchor | Keep one run-level delegated evidence section with `id="delegated-evidence"` on `/scoria/workflows/:run_id`. |
| Anchor CTA | The only primary navigation action inside the section is `Inspect Delegated Evidence`, linking to `#delegated-evidence`. |
| Empty state | Empty delegated evidence is a valid default-lane state, not a warning or setup failure. |
| Pending state | Show `child step pending` when the handoff is recorded but no delegated child-step readback exists yet. |
| Populated state | Show same-run lineage, execution status, projected-context preview, and full context disclosure together in each delegated handoff card. |
| Disclosure | Keep `View full context` as a native `<details>` disclosure; default collapsed, keyboard-operable, no custom JavaScript. |
| Layout | Keep delegated cards in the existing neutral evidence panel. Use a two-column preview at medium width and up; allow full-width stacking on small screens. |
| Data boundary | Render only curated `detail.delegated_handoffs` data from `Scoria.get_run_detail/1`; do not expose raw workflow table names or internal query paths. |

Primary focal point: the `Delegated Evidence` section header and `Inspect Delegated Evidence` anchor. Secondary hierarchy is delegated status, same-run lineage, then projected-context preview.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | Inspect Delegated Evidence |
| Empty state heading | No Delegated Handoffs Recorded |
| Empty state body | This run stayed on the default runtime lane. No bounded handoff is required for first adoption; use `Scoria.start_handoff_run/3` only when a same-run delegation needs narrow projected context. |
| Error state | Delegated evidence could not be loaded from the curated run detail. Refresh the workflow page, then verify the run through `Scoria.get_run_detail/1`. |
| Destructive confirmation | none; Phase 53 introduces no destructive operator action |

Docs wording requirements:

- Use direct modal phrasing: "start here", "add this only when", and "you do not need".
- State that `mix test.adoption` proves the default runtime lane.
- Do not publish a placeholder runtime-to-handoff proof command; Phase 54 owns that command.
- Do not imply bounded handoff is required for first adoption.
