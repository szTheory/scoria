## v2.4 Scope

**Goal:** Keep adopter and maintainer verification truth boring by pinning lane contracts across docs, tests, CI, warnings, and installer behavior.

**Requirements mapped:** 10 / 10

| Phase | Name | Goal | Requirements |
|------:|------|------|--------------|
| 55 | Lane Contract Source | Centralize lane command/env/prereq/exclusion truth into one contract | LANE-01, LANE-02 |
| 56 | Executable Support Truth | Bind docs drift guards to lane contracts and preserve canonical wording boundaries | DOCS-01, DOCS-02 |
| 57 | Warning And CI Trust | Resolve known warning debt, track baseline ownership, and enforce warning/lane checks in CI | WARN-01, WARN-02, CI-01, CI-02 |
| 58 | Installer Contract Hardening | Extend installer contract coverage for browser list-form scopes while preserving idempotency | INST-01, INST-02 |

## Phase Details

### Phase 55 — Lane Contract Source

**Goal:** Introduce one canonical lane contract for all verification lanes.

**Success criteria:**

1. Canonical lane list includes release-preview, adoption, runtime-to-handoff, semantic fast-path, and optional knowledge lanes.
2. Each lane has command, CI command, environment, prerequisites, and exclusions.
3. Closeout lane order is derived from the same contract source.

### Phase 56 — Executable Support Truth

**Goal:** Make support/docs wording enforceable through lane-contract-aware drift tests.

**Success criteria:**

1. Drift tests read canonical lane commands and boundaries from lane contracts.
2. Required default-lane boundary wording remains enforced.
3. Unsupported alias regressions remain blocked.

### Phase 57 — Warning And CI Trust

**Goal:** Close high-signal warning debt and enforce warning/lane policy in CI.

**Success criteria:**

1. `mix scoria.release_preview` runs docs with warnings-as-errors and passes.
2. Warning baseline exists with owner+expiry tracking for remaining accepted debt.
3. CI enforces compile warnings-as-errors and contract-critical warning checks before closeout lanes.
4. CI lane order remains `release_preview -> adoption -> runtime_to_handoff`.

### Phase 58 — Installer Contract Hardening

**Goal:** Keep installer behavior truthful and idempotent across supported browser-scope forms.

**Success criteria:**

1. Installer supports root browser scopes that use list-form `pipe_through`.
2. Installer output remains truthful for installed/already-present/skipped categories.
3. Installer tests cover new supported root-scope variants without architecture redesign.

## Non-Goals (v2.4)

- No new runtime capability family.
- No broad installer `plan/apply` rewrite in this milestone.
- No immediate zero-warning policy across all legacy surfaces.
