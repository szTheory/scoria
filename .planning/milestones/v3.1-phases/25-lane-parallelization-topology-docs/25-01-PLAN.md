<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| PR branch → required merge gate (`CI / ci-gate`) | An attacker or a careless config change crosses here; a false-green lets unverified code merge. |
| Parallel lane job → `verify-summary` fan-in | Each lane's result must be aggregated; an unwired or skipped lane must not silently pass. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-25-01 | Tampering | `verify-summary` aggregation | mitigate | Name-agnostic `join(needs.*.result)` loop treats any non-`success` (including `skipped`) as failure; adding a lane to `needs:` auto-includes its result — no per-child bash to forget to update. |
| T-25-02 | Repudiation/Bypass | A new parallel lane added later but not wired into `verify-summary.needs` | mitigate | Derived fan-in-completeness contract test (D-02) parses jobs with `needs: build`, asserts SUBSET of verify-summary.needs, with a non-empty guard so a broken regex cannot vacuously pass — an unwired lane turns the suite red. |
| T-25-03 | Tampering | `ratchet:` job mistakenly carrying Postgres `services:` | accept→mitigate | Contract test asserts only test/knowledge/connector bodies have `services:` and ratchet/policy/build/verify-summary do not — drift is caught. |
| T-25-04 | Elevation/Bypass | `CI / ci-gate` required-check name changes, dropping branch protection | mitigate | ci.yml `ci-gate` job + `needs: [verify, e2e]` left untouched; contract test `"ci.yml delegates to ci-verify..."` keeps asserting `ci-gate`. |
| T-25-SC | Tampering | npm/pip/cargo installs | accept | No package-manager installs in this phase (RESEARCH §"Package Legitimacy Audit": N/A); no supply-chain surface introduced. |
</threat_model>
