## Overview

v3.2 Drydock made local multi-lib Phoenix dev hands-off and port-conflict-free, hardened Scoria as the reference Docker dev-DX standard, and cut the queued `0.1.2` maintenance release. ## Milestone Summary

**Key Decisions:**

- `PORT ?= 4799` is the stable dev default; no `config/dev.exs` port rewrite.
- `make nuke` uses `docker compose down -v` only; no daemon-wide prune.
- Stream B (Phase 35) was treated as independent of Stream A and archived with the milestone.
- `VerificationLanes.closeout_order/0` and `CI / ci-gate` stayed byte-stable throughout the milestone.
- The router-derived launch banner and the `docs/docker_dev_dx.md` contract are both generated from source truth, not hand-maintained copy.
- The local registry upgrade proof for `0.1.2` uses previous live Hex release `0.1.0`.

**Issues Resolved:**

- Fixed the Makefile entrypoint and cleanup ladder so local dev is hands-off and scope-safe.
- Eliminated the launch-banner drift by deriving the route list from `mix phx.routes`.
- Verified Dockerfile cache ordering for CSS/HEEx-only edits and documented the invariant.
- Replaced plaintext-secrets guidance with a process-scoped pattern and closed the local key exposure concern.
- Reworked the dev-DX docs surface, then pinned it with a dedicated policy-lane contract.
- Completed the release and post-publish smoke path for `0.1.2` on live Hex.

**Issues Deferred:**

- `SEED-004` test-code determinism remains next-milestone work.
- `FLEET-01` sibling-repo convergence remains out of scope.
- `FLEET-02` fleet-wide `make nuke-all` remains out of scope.
- `ci-policy-job-cache-key-mislabel` remains a post-ship cleanup todo.
- `make-approval-toasts-legible` remains a UI follow-up todo.

**Technical Debt:**

- `DXCLI-03` wording is broader in implementation than the traceability text.
- `DXCLI-05` wording uses `localhost:4799` in the banner path while the older requirement text mentions `127.0.0.1`.
