# Milestone v1.2: Corpus

**Status:** ✅ SHIPPED 2026-05-11
**Phases:** 6-6
**Total Plans:** 6

## Overview

Phase 6 added a durable RAG and grounding layer to Scoria. The milestone ships pgvector-backed retrieval, durable provenance, machine-readable citations, deterministic grounding checks, and trace-first evidence projection in the existing dashboard surface.

## Phases

### Phase 6: Advanced RAG, Citations & Knowledge Grounding

**Goal**: Provide batteries-included RAG primitives that natively integrate with the Scoria trace tree and Eval Workbench.
**Depends on**: Phase 1 and Phase 4, with the existing LiveView surface used for projection
**Plans**: 6 plans

Plans:

- [x] 06-00: pgvector Bootstrap and Knowledge Test Scaffold
- [x] 06-01: Durable Knowledge Foundation
- [x] 06-02: Retrieval Backend Boundary
- [x] 06-03: Retrieval Provenance and Citation Contract
- [x] 06-04: Grounding Evaluation Ladder
- [x] 06-05: Trace-First Evidence Projection

**Details:**

- Wave 0 added a pgvector bootstrap task, local compose assets, and a shared vector-aware test scaffold so the milestone could fail fast when the extension was unavailable.
- The knowledge foundation introduced durable `Source`, `Chunk`, `Citation`, `RetrievalRun`, `RetrievalResult`, and `GroundingScore` nouns behind `Scoria.Knowledge`.
- Retrieval stayed behind a narrow backend boundary with pgvector as the default and Scrypath normalized as an optional adapter only.
- Retrieval logging persisted ordered runs and results with machine-readable citation anchors linked to trace/span provenance.
- Grounding checks were deterministic first, with versioned judge review appended only as a second layer.
- Evidence projection stayed trace-first and lazy-loaded inside the existing dashboard instead of creating a separate RAG application.

## Milestone Summary

**Key Decisions:**

- pgvector is the boring default retrieval backend; all other retrieval engines remain behind adapter seams.
- `Scoria.Knowledge` is the single public context for corpus, retrieval, citation, and grounding work.
- Deterministic citation and grounding checks gate judge review.
- Operator evidence stays inside the existing LiveView surface and loads asynchronously to avoid long-lived socket bloat.

**Issues Resolved:**

- Added explicit pgvector bootstrap guidance for hosts that do not expose the `vector` extension.
- Kept citation anchors durable and machine-readable instead of storing rendered text only.
- Preserved Scrypath as an optional retrieval-source adapter rather than letting it own corpus truth.

**Issues Deferred:**

- Manual readability validation for long evidence bodies remains the one human-only follow-up from the validation plan.

**Technical Debt:**

- The default local PostgreSQL instance on `localhost:5432` still lacks `vector`; Phase 6 verification assumes the bundled pgvector-capable service or an equivalent host.
