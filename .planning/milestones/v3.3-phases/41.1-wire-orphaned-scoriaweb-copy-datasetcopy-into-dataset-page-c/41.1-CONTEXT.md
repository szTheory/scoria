<decisions>
## Implementation Decisions

### D1 — UI.status_label/1 delegates to Copy.status_label/1 (LOCKED)
`ScoriaWeb.UI.status_label/1` currently reimplements the exact same 13-entry status map as `ScoriaWeb.Copy.status_label/1`. Resolve the duplication by making `UI.status_label/1` **delegate to** `Copy.status_label/1` and deleting UI's inline `case`.

- **This does NOT reverse the Phase 39-02 locked decision.** That decision (STATE.md) said *"Copy.status_label/1 independently curates the D-25 vocabulary rather than delegating to UI.status_label/1 — keeps Copy a dependency-free leaf module."* It constrains the dependency **direction**: `Copy` must not depend on `UI`. Delegating `UI → Copy` keeps `Copy` a dependency-free leaf (verified: `copy.ex` has zero `ScoriaWeb.UI` references; `ui.ex` has zero `ScoriaWeb.Copy` references today). D-24b ("Copy is data, UI is the renderer") is honored — the renderer consumes the data module.
- Behavior must stay identical: `Copy.status_label/1` returns byte-identical labels for all 13 curated statuses plus the same `humanize` fallback, and `status_label(nil)`/`status_label(_)` → `"Unknown"` matching UI's current `status_label(_) -> "Unknown"`. Verify parity before deleting UI's map (a table test over the 13 keys + nil + an unseen key).

### D2 — Empty-state title from Copy; preserve visible CTA copy (LOCKED w/ guardrail)
`dataset_live/index.ex` empty-state title literal `"No datasets match this view"` is **byte-identical** to `Copy.empty_title(:datasets)` → wire it (zero visible change).

- The empty-state CTA currently reads `"Adjust your filters or check back when data is available."` This is a **filtered-empty** CTA and is semantically different from `Copy.empty_cta(:datasets)` = `"Promote a production trace to start a regression suite."` (a truly-empty CTA). **Do not silently swap it** — that would change operator-visible copy that passed COPY-01.
- Resolution: make `Copy` the source of truth for the CTA **without changing the rendered bytes.** Preferred approach: route the CTA through a `Copy` function whose returned string is byte-identical to today's visible copy (the generic `Copy.empty_cta(_domain)` is the closest — `"Adjust your filters or check back once new data arrives."` — but it is NOT byte-identical; either align the page to an existing Copy string only if the owner accepts the wording, or add/keep a dedicated filtered-view CTA source). If no byte-identical `Copy` home exists, the planner may (a) keep the CTA inline **and record it explicitly** as a known non-SSOT string with a code comment + gap-register note, or (b) add a minimal `Copy` accessor returning today's exact string. **Default: preserve the exact current CTA wording; SSOT-wire it only if the string stays byte-stable.** Any wording change is an owner decision, surfaced in the plan, not made silently.

### D3 — Dataset state label + version via DatasetCopy; tone stays local (LOCKED)
- Replace `dataset_live`'s local `defp state_label/1` (`:open`→"Open", `:sealed`→"Sealed", `_`→"Unknown") with `DatasetCopy.state_label/1`. Note the fallback differs (`DatasetCopy` returns `"State not recorded"` for unknown vs local `"Unknown"`). For the known states (`:open`/`:sealed`) the visible label is byte-identical; the unknown-state fallback is not reachable with today's seed data (state is always `:open`/`:sealed`), so adopting `DatasetCopy`'s fallback is acceptable — confirm no fixture/test asserts the `"Unknown"` string.
- `defp state_tone/1` (`:open`→`:info`, `:sealed`→`:pass`, `_`→`:neutral`) is a **rendering** concern (a badge tone atom), not copy. It STAYS local — `Copy`/`DatasetCopy` render nothing (zero `~H`, D-24b) and expose no tone.
- Route the `v{dataset.version}` inline displays (index.ex:103, :127) through `DatasetCopy.version_label/1` where it reads as an operator label. Where `v{version}` is a compact inline evidence token rather than a standalone label, the planner may leave it — but `version_label/1` must gain at least one real caller so it is no longer orphaned. `DatasetCopy.orientation/1` may be wired where a dataset-orientation line belongs, or explicitly documented as intentionally unused-in-this-page if the dataset page has no orientation surface (it must not be left silently orphaned without a note).

### D4 — Regression guard (LOCKED)
Add/extend a guard so the wired call sites cannot silently regress to inline literals or a re-duplicated status map. Prefer extending the existing `copy_guard_test.exs` (warning-grade source-scan, page-scoped) or `copy_test.exs` (unit parity). At minimum: (a) a parity test proving `UI.status_label/1 == Copy.status_label/1` across the curated vocabulary so a future divergence fails; (b) a caller-presence or literal-absence assertion for the dataset empty-state title. Follow the existing allow-list / descriptive-failure guard style — do not invent a new framework.
