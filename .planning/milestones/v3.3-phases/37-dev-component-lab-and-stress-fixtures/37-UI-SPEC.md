# Phase 37 — UI Design Contract

> Visual and interaction contract for the dev-only Component Lab. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **Governing rule for this phase:** the lab is an *inspection tool for existing tokens and primitives*, not a new visual surface. Every value below is lifted verbatim from `brandbook/tokens.json` / `assets/css/02-tokens.css` (runtime SSOT) and `lib/scoria_web/ui.ex` (component SSOT). Phase 37 must not invent new colors, type sizes, spacing steps, or primitive variants — it renders what already exists, in more states, at more widths. Any drift found (see Typography Weights below) is logged as Phase 38 scope (DS-02/DS-03), not fixed here.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none (Elixir/Phoenix library — no npm/shadcn toolchain; no `components.json`/`package.json` in repo) |
| Component library | `ScoriaWeb.UI` (Phoenix function components, `attr`/`slot` contracts) — canonical, in-repo |
| Icon library | none — inline 16×16 SVGs authored directly in `ui.ex` (tone icons for badge/toast/flash; a11y rule: status is never color-alone) |
| Font | `IBM Plex Sans` (UI text) / `JetBrains Mono` (IDs, code, raw evidence) — declared in `--scoria-font-sans` / `--scoria-font-mono`, `assets/css/02-tokens.css` |

Source of truth for every token below: `brandbook/tokens.json` (docs SSOT) and `assets/css/02-tokens.css` (runtime SSOT). Per `brandbook/README.md`, hexes must stay identical between the two; the lab must not fork a third copy.

## Spacing Scale

Declared values (existing runtime scale — `--scoria-space-*`, all multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| space-1 | 4px | Icon gaps, inline padding, badge padding |
| space-2 | 8px | Compact element spacing, kbd chip padding |
| space-3 | 12px | Form field gaps, table cell padding |
| space-4 | 16px | Default element spacing, panel body padding |
| space-5 | 24px | Section padding, page-section gaps |
| space-6 | 32px | Layout gaps between page sections |
| space-7 | 48px | Major section breaks |
| space-8 | 64px | Page-level spacing |
| space-9 | 96px | Rare hero/marketing-scale spacing (docs/brandbook only; not expected inside the lab shell) |

**Exceptions for this phase:**
- Lab-specific chrome (section nav rail, state-band dividers, viewport-simulator frame) must compose from `space-1`–`space-6` only; do not introduce a new spacing primitive for lab layout.
- Icon-only touch targets (icon buttons in lab toolbar — e.g. "copy fixture payload", theme toggle inside the lab) follow the existing `scoria-button--icon` sizes already defined in `ui.ex`/`04-components.css`; do not redefine touch target sizing for the lab.

## Typography

Existing runtime scale (`--scoria-fs-*` / `tokens.json` → `typography.size`). This exceeds the usual 3–4 size guideline because it is the **existing locked brand system** (shipped v2.17, inventoried in Phase 36) — Phase 37 must reuse it exactly, not trim it.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Badge / eyebrow | 11px | 600 (semibold) | 1.2 (tight) |
| Label | 12px | 600 (semibold) | 1.2 (tight) |
| Body | 14px | 400 (regular) | 1.5 (body) |
| Panel heading | 18px | 600 (semibold) | 1.2 (tight) |
| Title | 24px | 600 (semibold) | 1.2 (tight) |
| Display / Metric | 30px | 600 (semibold) | 1.2 (tight) |

**Canonical two-weight rule for anything new the lab authors (chrome, labels, headers): 400 regular + 600 semibold only.**

**Known existing drift (out of scope for Phase 37, do not fix here):** `04-components.css` also uses `font-weight: 500` (line 237), `650` (line 602), and `700` (line 853) on a few existing components. The lab should render these components as-is (they are real specimens of the drift the lab exists to surface) but must not introduce *new* uses of 500/650/700 in lab-authored chrome. Log this drift as visible input to Phase 38 DS-02/DS-03, not a Phase 37 fix.

Font family: `IBM Plex Sans` for all UI roles above; `JetBrains Mono` for `<.id>`, raw evidence/code blocks, and any lab-authored fixture-source/inventory-ID labels (D-29 evidence-oriented details).

## Color

Runtime is theme-aware (light/dark/system, per `.scoria-root[data-theme]`). Values below are **semantic tokens**, not new hexes — dark shown as primary reference, light is the re-pointed pair from the same `tokens.json`.

| Role | Value (dark) | Value (light) | Usage |
|------|-------|-------|-------|
| Dominant (60%) | `--scoria-surface-app` `#11100f` | `#faf5ef` | Lab shell background, page canvas |
| Secondary (30%) | `--scoria-surface-panel` `#181513` / `--scoria-surface-panel-raised` `#211c19` | `#fff9f3` / `#ffffff` | Lab section panels, specimen cards, nav rail, viewport-simulator frame |
| Accent (10%) | `--scoria-action` / `--scoria-link` `#e65a32` (dark) | `#b94f31` (light) | Reserved for: primary lab commands (`Run lab proof`, `Open fixture matrix`), active nav-rail item, focus ring (`--scoria-focus-ring`), links, brand-tone badges (`:brand`) |
| Destructive | `--scoria-danger-action` `#ff6b4a` (dark) / `#9e2f20` (light) | — | Destructive-action affordances only (none native to the lab itself — the lab never mutates data; destructive-tone fixtures like `approval_denied`/`incident_opened` render via existing `:fail` tone, not a lab-specific destructive control) |

**Accent reserved for (explicit list — never "all interactive elements"):** the lab's own primary/secondary commands (`Run lab proof`, `Open fixture matrix`), the active item in the lab's section nav (Foundations/Primitives/Groups/States/Viewports/Overlays/Fixtures), focus rings on any focusable lab control, and `:brand`-tone badges when a specimen fixture explicitly needs that tone. All other lab chrome (headers, labels, dividers, non-active nav items) uses neutral/muted text and border tokens (`--scoria-text-muted`, `--scoria-border`).

**Tone vocabulary (unchanged, reused as-is — this is the DS-05 tone system, not new colors):** `:neutral`, `:pass`, `:info`, `:warn`, `:fail`, `:trace`, `:brand`, each with `-fg`/`-bg`/`-border` triplets in both themes. Per D-12, lab **state** names (`normal`, `long_text`, `empty`, `dense`, `disabled`, `selected`, `loading`, `warning`, `danger`, `error`) are a separate vocabulary from these visual **tones** — a lab state band labeled `warning` renders using tone `:warn`, but the band label itself is never a tone name.

Locked in 37-CONTEXT.md D-27 — reproduced here as the binding contract (do not paraphrase):

| Element | Copy |
|---------|------|
| Page title | `Component Lab` |
| Subtitle | `Inspect Scoria primitives, groups, fixtures, themes, and stress states before changing shared UI.` |
| Primary CTA | `Run lab proof` |
| Secondary command | `Open fixture matrix` |
| Empty state heading | (none separate — single-line copy per D-27) |
| Empty state body | `No fixture rows for this state. Add deterministic dev fixture data before using this state for proof.` |
| Error state | `Lab fixture failed to render. Check the fixture builder and component attrs before changing runtime UI.` |
| Destructive confirmation | Not applicable — the lab performs no destructive actions; decided/denied approval states are rendered as read-only fixture specimens, not live actions |

**Lab chrome labels (D-27):** `Reduced motion`, `Ugly data`, `Dense data`, `Long text`, `Technical evidence`, `Copy fixture payload`.

**IA section labels (D-07, exact, top-level nav):** `Foundations`, `Primitives`, `Groups`, `States`, `Viewports`, `Overlays`, `Fixtures`.

**Canonical state-band labels (D-11, exact vocabulary — never invent synonyms):** `normal`, `long_text`, `empty`, `dense`, `disabled`, `selected`, `loading`, `warning`, `danger`, `error`.

**Viewport labels (D-13):** label as maintainer proof targets, not marketing — e.g. `320px — small mobile`, `375px — mobile`, `768px — tablet`, `1024px — small desktop`, `1440px — desktop`, `Wide desktop`. Never use device marketing names (e.g. "iPhone SE").

**Voice constraint (D-25, D-28, D-29):** field-engineer-bench / evidence-notebook tone — components are "specimens under stress," not demo cards. Hide Ecto schema names, PubSub topics, private helpers, raw maps, macro mechanics, and route internals from primary orientation; surface them only inside evidence disclosures (trace/run/approval/actor/session/tenant IDs, policy/version names, payloads, fixture source labels, inventory refs `PRIM-TABLE`/`GROUP-APPROVAL-INBOX-COMPONENT`/etc., risk refs `RISK-RESPONSIVE-SCAN`/`RISK-OVERLAY-FOCUS`, and component owner names like `ScoriaWeb.UI.table/1`).

## Component Inventory For Lab Chrome (reuse only — do not add new primitives)

The lab's own chrome (nav rail, section headers, state-band labels, viewport indicator, fixture-source tag, inventory-ID chip) must be built from these existing `ScoriaWeb.UI` primitives, not new ones:

| Need | Existing primitive |
|------|--------------------|
| State-band label / tone chip | `badge/1` (with `tone/1` mapping) |
| Section eyebrow / category label | `eyebrow/1` |
| Viewport-width indicator, keyboard hints | `kbd/1` |
| Fixture-source / inventory-ID / trace-ID chip | `id/1` (copyable monospace) |
| Section container | `panel/1`, `page_section/1` |
| Specimen empty case | `empty_state/1` |
| Specimen loading case | `skeleton/1` |
| Overlay probes (drawer/modal/toast focus & dismissal) | `drawer/1`, `modal/1`, `toast/1` |
| Raw fixture payload disclosure | `raw_evidence/1`, `notebook/1`, `evidence_section/1`, `evidence_rows/1` |
| Stats/metric specimens | `metric/1`, `overview_stats/1`, `signal_strip/1` |

If a genuinely new lab-only chrome need arises (e.g. a viewport-simulator frame or a section nav rail) that has no existing primitive, keep it internal to `dev/` per D-06/Claude's Discretion, and it must still consume semantic tokens only (`--scoria-*` custom properties) — never a raw hex or a new spacing/type value.

## Motion & Theme Coverage (contract, not new tokens)

- Theme coverage required: light, dark, system (D-14). Use existing `.scoria-root[data-theme]` toggle mechanism (`assets/js/scoria.js` theme hook) — do not add a second theme mechanism inside the lab.
- Motion tokens are existing (`assets/css/05-motion.css`: `--scoria-ease-out`, `--scoria-ease-in-out`, `--scoria-dur-fast/mid/slow` = 100/150/200ms). Phase 37 must make `prefers-reduced-motion` behavior *visible and testable* (a "Reduced motion" toggle/label per D-27) but must not invent new motion language or durations.
- Viewport coverage required: 320, 375, 768, 1024, 1440, wide desktop (D-13) — these are proof targets, implemented via a CSS/JS width-simulator or literal browser-resize proof script (`priv/dev/e2e/`), not new breakpoint tokens.
