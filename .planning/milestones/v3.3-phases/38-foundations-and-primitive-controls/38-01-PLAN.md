<objective>
Fix the "transparent unreadable toasts" defect (Criterion 4 · DS-04) by giving toasts (and floating
flashes) an opaque status surface, without disturbing the correct translucent in-page tone tints.

Purpose: Approval warning/error toasts currently render the shared translucent `--scoria-tone-*-bg`
tint directly, so page content bleeds through over the dense approvals table. This plan introduces
opaque toast-specific tone tokens composited over an already-solid surface, repoints the toast/flash
CSS at them, and locks the fix with a new CSS-source guard plus an extended browser assertion.

Output: `--scoria-toast-<tone>-bg` tokens (both themes), repointed `.scoria-toast--<tone>` /
`.scoria-flash--<tone>` rules, a new `toast_opacity_guard_test.exs`, and a computed-style alpha
assertion added to the existing dense-approvals+toast e2e block.
</objective>
