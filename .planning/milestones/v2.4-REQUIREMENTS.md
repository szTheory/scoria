# Requirements: Scoria

**Defined:** 2026-05-27  
**Core Value:** Phoenix teams can add AI runtime governance, visibility, and recovery to an existing app without guessing where Scoria begins, where their app owns identity and policy, or how to verify the integration is working.

## v2.4 Requirements

Requirements for the `v2.4 Adoption Reliability Contract` milestone.

### Lane Contracts

- [x] **LANE-01**: Maintainers can read one machine-readable contract that defines command, environment, prerequisites, and exclusions for every canonical verification lane.
- [x] **LANE-02**: Canonical closeout lane order (`release_preview -> adoption -> runtime_to_handoff`) is represented in the same contract source and consumable by tests.

### Docs And Drift Guards

- [x] **DOCS-01**: Adopter/support docs drift tests consume lane contract commands and boundary phrasing rather than duplicated string literals.
- [x] **DOCS-02**: Drift guards fail when canonical lane wording drops required lane boundaries or reintroduces unsupported command aliases.

### Warning Trust

- [x] **WARN-01**: `mix scoria.release_preview` treats docs warnings as errors and passes without known release-preview warning debt.
- [x] **WARN-02**: Remaining warning debt is tracked in a scoped baseline ledger with explicit owner and expiry fields.

### CI Enforcement

- [x] **CI-01**: CI runs compile warnings-as-errors and contract-critical warning checks before canonical lane closeout commands.
- [x] **CI-02**: CI preserves canonical lane ordering for release-preview, adoption, and runtime-to-handoff verification surfaces.

### Installer Contract

- [x] **INST-01**: `mix scoria.install` remains idempotent and truthful when root browser scope uses list-form `pipe_through` syntax.
- [x] **INST-02**: Installer tests prove browser-scope list forms are patched without widening installer architecture scope.

## Future Requirements

Deferred beyond `v2.4`:

- **INST-03**: Installer `--dry-run` / `--check` plan/apply semantics.
- **INST-04**: Installer manifest-based drift detection and upgrade-safe mutation plans.
- **WARN-03**: Full-suite warning budget ratchet across all legacy surfaces.

## Out of Scope

| Feature | Reason |
|---------|--------|
| New runtime capability families | `v2.4` is reliability-contract work, not capability expansion |
| Broad installer engine rewrite | Deferred to dedicated installer-v2 milestone |
| Zero-warning policy across all legacy tests immediately | Too broad for a scoped reliability closeout; baseline first |
