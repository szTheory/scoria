| Token | Value | Usage |

| sm | 8px | Compact element spacing, nav rows, inline controls |
| md | 16px | Default element spacing, panel body rhythm |
| lg | 24px | Section padding, page header bottom rhythm |
| xl | 32px | Layout gaps, main content padding on desktop |

| 3xl | 64px | Page-level spacing only; not needed for Phase 44 additions |

Exceptions: Existing runtime token `--scoria-space-3: 12px` may be used only through established components for dense dashboard internals. Existing mobile shell controls keep the 44px minimum hit target. Phase 44 must not introduce new raw spacing values or new page-level gaps.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | Open dashboard |
| Empty state heading | Dashboard unavailable |
| Empty state body | This Scoria dashboard is not available for this session. |
| Error state | This Scoria dashboard is not available for this session. |
| Destructive confirmation | None - Phase 44 adds no destructive action or confirmation UI. |

Copy rules:

- Browser-facing auth/scope failure copy must stay generic and must not reveal tenant IDs, tenant lists, resolver internals, session keys, hook names, membership checks, or exact policy failure reasons.
- Developer detail belongs in docs, logs, and tests, not in operator-facing UI.
- If host resolver returns `{:redirect, to}` or `{:halt, socket}`, host-controlled copy may take over outside the Scoria dashboard. Scoria-owned fallback copy stays exactly as above.
- If `?tenant=` is present and ignored, do not render an explanatory warning. The dashboard should simply use the host-asserted scope or fail closed.

## Phase 44 Interaction Contract

### Successful Scoped Session

- Preserve the existing `/scoria` dashboard shell, navigation groups, page headers, table controls, empty states, overlays, command palette, theme toggle, and responsive behavior.
- Do not add a tenant picker, account switcher, cross-tenant mode, role selector, policy selector, or authorization-management UI.
- Do not add a new route, modal, drawer, or onboarding screen for this seam.
- Dashboard pages must consume `socket.assigns.scoria_scope` or `socket.assigns.tenant_id` only. Query params may affect ordinary UI filters, but never tenant authority.

### Missing Or Unauthorized Scope

- Halt before dashboard data reads, object hydration, PubSub subscriptions, or tenant-owned list rendering.
- If Scoria renders the failure, use existing `empty_state/1` or `flash_group/1`/`.scoria-flash--fail`; do not invent a new failure component or raw CSS class.
- Render only the generic copy from the Copywriting Contract.
- Keep the unavailable state visually quiet: dominant app background, one secondary panel/empty-state surface at most, no decorative illustration, no stack trace, no resolver diagnostics.

### Optional Read-Only Scope Receipt

- Optional only; omit it if the implementation can satisfy AUTH-01..03 without visible scope chrome.
- If implemented, place it in existing shell/page-header chrome as a compact read-only receipt, not as a control.
- Label: `Scope`.
- Value source: host-provided safe display label such as `display_tenant`; omit the receipt if no safe display label exists.
- Visual treatment: existing badge/evidence-row style, neutral or info tone, 12px label/meta scale, 8px inline gap.
- Accessibility: expose a stable accessible name such as `Current dashboard scope: {display_tenant}`.
- Prohibited: dropdown chevron, hover menu, click handler, link, raw tenant ID as primary operator copy, cross-tenant count, "switch", "manage", "authorize", or any wording that implies Scoria owns tenant membership.

### Object And Empty States

- Existing legitimate no-data states remain page-specific, for example "No runs match this view" or "No prompt versions yet."
- Cross-tenant object detail attempts should render the existing not-found or unavailable empty-state pattern, not a security explanation.
- Object detail copy may say the object is not available for the current tenant only if it does not reveal that another tenant owns it.

### Loading And Motion

- Use existing skeleton, flash, toast, modal, drawer, and command-palette motion tokens only.
- No new animation is needed for Phase 44.
- Reduced-motion behavior must continue to be governed by the existing motion guardrails.

## Component Contract

Use existing components and classes only:

| Need | Required Surface |
|------|------------------|
| Page heading | `page_header/1` or existing page-specific header; preserve exactly one page header |
| Generic unavailable state | `empty_state/1` or `flash_group/1` with fail tone |
| Optional scope receipt | existing `badge/1`, `evidence_rows/1`, or compact page-header action pattern |
| Inline status | `badge/1` with visible text; status is never color-only |
| Buttons | `button/1`, `icon_button/1`, or existing `.scoria-button` variants |
| Panels | `panel/1` / `.scoria-panel`; no nested cards |
| Tables/detail lists | existing table and evidence primitives |

No new raw hex, rgb, Tailwind palette class, one-off selector, layout shell, card system, or typography class may be introduced for this phase. Any asset CSS change must be rebuilt into `priv/static/scoria/app.css` with the existing asset build path.

---

## Accessibility Contract

- Failure surfaces use `role="alert"` only when rendered as a flash/banner. A static empty state should not announce repeatedly.
- Icon-only controls keep accessible names. Phase 44 should not add new icon-only controls.
- All focus indicators use `--scoria-focus-ring`; never suppress focus styles.
- Mobile controls preserve the existing 44px minimum hit target.
- Text must meet the existing WCAG AA token constraints. Do not use `--scoria-text-subtle` for body copy or failure explanations.
- The optional scope receipt must remain readable in dark and light themes and must not truncate in a way that hides the host-provided display label without an accessible full label.
