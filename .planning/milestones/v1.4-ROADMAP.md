# Milestone v1.4: Keystone

**Status:** ✅ SHIPPED 2026-05-17

## Overview

Phases 12 through 18 turned Scoria's durable workflow, governance, and operator substrate into a clearer Phoenix-facing product surface. Keystone shipped canonical runtime identity, a public `Scoria` runtime API, predictable defaults and install ergonomics, adoption docs aligned to the public boundary, verification backfills for the earlier phase gaps, and executable guardrails that keep the adoption story from drifting.

## Milestone Summary

**Key Decisions:**

- Keep Scoria embedded and Phoenix-first rather than widening into a hosted runtime product.
- Make actor, tenant, and session identity explicit before expanding connector breadth or release-ops surface area.
- Teach the public product through `Scoria` first, with lower-level modules remaining available but not the default adoption path.
- Treat adoption docs as executable contracts where practical instead of prose-only guidance.

**Issues Resolved:**

- Replaced ad hoc runtime identity handling with one canonical boundary contract.
- Exposed a stable public runtime facade for start, resume, inspect, and session-oriented lifecycle work.
- Closed the milestone's missing verification chain by backfilling canonical phase-local verification artifacts.
- Reduced docs drift risk by adding executable adoption guards and a named acceptance lane.

**Issues Deferred:**

- Remote MCP connector breadth remains deferred to likely `v1.5 Switchyard`.
- Prompt/version release operations remain deferred to likely `v1.6 Flightpath`.
- `SEED-001-agentcore-lessons` remains acknowledged for future milestone review.

**Technical Debt:**

- The historical `.planning/v1.4-MILESTONE-AUDIT.md` remains a dated pre-backfill snapshot; current shipped truth now lives in Phase 12-18 artifacts.
- Public naming still carries mild knowledge-lane friction between `mix scoria.test.knowledge` and compatibility references to `mix test.knowledge`.
