# Milestone v1.6: Flightpath Requirements

**Status:** Shipped
**Theme:** Release gates, prompt lifecycle, and evaluation operations
**Last updated:** 2026-05-19

## Milestone Goal

Establish a closed-loop LLM evaluation flywheel entirely within the embedded Scoria architecture. Traces become curated datasets, datasets drive deterministic ExUnit regression pipelines, and evaluation runs provide the evidence required to unlock operator-approved release gates for versioned prompts.

## In Scope Requirements

### Prompt Registry & Lifecycle

- [x] **REG-01**: System provides an Ecto-backed prompt registry that stores versioned, immutable prompt templates and tracks lifecycle status (draft, active, archived).
- [x] **REG-02**: Prompts are modeled as structured maps (System Message, Few-Shot Examples, User Template) supporting variable interpolation, rather than fragile raw strings.
- [x] **REG-03**: Registry includes token estimation capabilities (via Elixir Tiktoken port) to warn operators of context window limits before saving.

### Datasets & Curation

- [x] **DATA-01**: Operators can curate real production traces from Scoria's observability layer into durable `Dataset` records via the embedded LiveView UI.
- [x] **DATA-02**: Datasets natively capture structured inputs, baseline expected outputs, and multi-turn context to support accurate offline recreation.

### CI/CD Regression & Evaluation

- [x] **EVAL-01**: System provides an ExUnit-integrated evaluation runner capable of executing Datasets against draft prompt versions.
- [x] **EVAL-02**: The evaluation runner mandates HTTP VCR/cassettes for standard test runs to prevent flaky, non-deterministic, and expensive LLM calls during CI.
- [x] **EVAL-03**: System provides an LLM-as-a-judge primitive utilizing structured outputs (e.g., via Instructor.ex) for durable, qualitative trace evaluation.
- [x] **EVAL-04**: Evaluation results are persisted durably to Ecto as `EvalRun` records linked to a specific runtime identity, dataset, and prompt version.

### Release Gates & Approvals

- [x] **GATE-01**: System enforces a release gate policy where a new draft prompt version cannot serve production traffic via `Scoria.Runtime` until explicitly approved.
- [x] **GATE-02**: Approval operations are integrated with Scoria's existing workflow-owned approval lineage, requiring operators to review `EvalRun` evidence before unlocking the gate.
- [x] **GATE-03**: An embedded LiveView workbench allows operators to visually compare draft prompt versions against active versions alongside their evaluation metrics.

## Future Requirements

- Automated production rollout (e.g., canary traffic shifting).
- Multi-model A/B testing workbench (comparing OpenAI vs Anthropic directly in UI).
- External dataset format export/import (JSONL) for fine-tuning pipelines.

## Out of Scope

- **Hosted external telemetry platform** — Scoria strictly remains an embedded Phoenix library; we do not accept HTTP telemetry from external apps.
- **Automated un-gated prompt promotion** — AI evaluations provide evidence, but humans must provide the final approval.
- **Direct orchestrating of model fine-tuning** — Scoria is not an MLOps pipeline runner.
