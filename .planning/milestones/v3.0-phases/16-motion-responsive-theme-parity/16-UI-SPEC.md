## Spacing Scale

All spacing resolves to `--scoria-space-N` primitives. New Phase 16 CSS must bind to existing tokens and remain scoped under `.scoria-root`.

| Token | Primitive | Value | Usage |
|-------|-----------|-------|-------|
| xs | `--scoria-space-1` | 4px | Icon gaps, badge dots, compact inline separators |
| sm | `--scoria-space-2` | 8px | Compact button padding, badge padding, drawer/topbar control gaps |
| md | `--scoria-space-4` | 16px | Default element gaps, panel padding, mobile summary padding |
| lg | `--scoria-space-5` | 24px | Section gaps, modal/drawer padding, page-header rhythm |
| xl | `--scoria-space-6` | 32px | Desktop main padding, major layout gaps |
| 2xl | `--scoria-space-7` | 48px | Empty-state vertical padding |
| 3xl | `--scoria-space-8` | 64px | Reserved page-level spacing |

Exceptions:
- `--scoria-space-3` = 12px remains a locked existing token for nav item padding, table default cell padding, form input inline padding, and compact grid gaps. Use it where existing component CSS already does.
- `--scoria-space-9` = 96px remains available only as an existing primitive; Phase 16 must not introduce it for new mobile/layout spacing.
- Interactive controls in the mobile topbar, nav drawer, rows, and overlay close buttons must maintain a minimum 44px hit target even when visual padding is smaller.
- Table scroll viewports may use `overflow-x: auto` and sticky positioning; those are layout behaviors, not spacing tokens.

## Typography

Contract: 4 type tiers and 2 weights. New UI must not introduce new type sizes or a third weight.

| Role | Token | Size | Weight | Line Height | Usage |
|------|-------|------|--------|-------------|-------|
| Display / page title | `--scoria-fs-display` | 30px | 600 | `--scoria-lh-tight` = 1.2 | Page titles and metric values |
| Panel heading | `--scoria-fs-panel` | 18px | 600 | `--scoria-lh-tight` = 1.2 | Drawer, modal, notebook, and panel headings |
| Body | `--scoria-fs-body` | 14px | 400 | `--scoria-lh-body` = 1.5 | Table cells, descriptions, form help, evidence values |
| Label | `--scoria-fs-label` | 12px | 400 or 600 | 1.45 | Table headers, form labels, breadcrumbs, metadata |

Declared weights:
- Regular: 400
- Semibold: 600

Existing implementation exception:
- `--scoria-fs-badge` = 11px remains allowed only inside existing badge/eyebrow CSS classes. New HEEx templates must emit `.scoria-badge`, `.scoria-eyebrow`, or existing component classes instead of binding directly to `--scoria-fs-badge`.
- Existing `.font-medium` utility maps to 500; Phase 16 should not introduce new 500-weight UI decisions. Prefer existing class cleanup when touching nearby markup.

## Color

All new and modified Phase 16 UI must use semantic tokens only. Do not add raw hex colors, primitive palette tokens, or raw Tailwind palette classes under `lib/scoria_web/`.

| Role | Token | Light Value | Dark Value | Usage |
|------|-------|-------------|------------|-------|
| Dominant (60%) | `--scoria-surface-app` | `#faf5ef` | `#11100f` | App background and shell field |
| Secondary (30%) | `--scoria-surface-panel` | `#fff9f3` | `#181513` | Sidebar, topbar panels, tables, cards |
| Raised surface | `--scoria-surface-panel-raised` | `#ffffff` | `#211c19` | Modal, drawer, selected evidence panels |
| Sunken surface | `--scoria-surface-sunken` | `#f1e8de` | `#0c0b0a` | Inputs, code, raw evidence blocks |
| Accent (10%) | `--scoria-action` | `#b94f31` | `#e65a32` | Reserved elements listed below |
| Destructive | `--scoria-danger-action` | `#9e2f20` | `#ff6b4a` | Destructive actions and error affordances only |

Accent reserved for:
- Primary `.scoria-button--primary` backgrounds and active density controls.
- Current nav indicator via `[aria-current="page"]` and active notebook tab underline.
- Active table sort indicator and focus ring token pair.
- Selected row or active object state through `--scoria-tone-brand-*`, paired with text/ARIA/structure.
- Brand mark/detail accents already present in the shell.

Accent is not a generic hover color. Hover states should use neutral tone backgrounds, border strength, or existing `--scoria-link-hover`.

Semantic status contract:
- `:pass`, `:info`, `:warn`, `:fail`, `:trace`, `:brand`, and `:neutral` flow through `ScoriaWeb.UI.tone/1`, `.scoria-badge--{tone}`, and semantic tone tokens.
- Status must never be conveyed by color alone. Pair color with text labels, icons, `aria-selected`, `aria-current`, visible rails with labels, or structural grouping.
- Light and dark themes are equal-priority surfaces. Fix contrast at semantic component/token usage level before adding screen-specific overrides.

Token changes:
- Do not edit `assets/css/02-tokens.css` for cosmetic preference.
- Token edits are allowed only for WCAG defects or real coherence breaks found in both-theme verification.

## Phase 16 Interaction Contracts

### Mobile Shell

Below `md` (`<768px`):
- `.scoria-shell` must become a single-column layout. The fixed 248px sidebar must not occupy mobile viewport width.
- Desktop `.scoria-sidebar` is hidden or removed from layout below `md`.
- A compact sticky mobile topbar must include brand/current page context, `Menu`, command palette access, and theme toggle access.
- Global breadcrumbs must be compact; object identity and provenance stay in `<.object_header>` and page content.
- Page-level horizontal overflow must be zero at 375px viewport width except inside intentional table/evidence scroll containers.

Primary visual hierarchy:
- On mobile, the sticky topbar is the first focal point because it carries orientation, navigation access, command access, and theme access.
- The page object header is the second focal point; it carries the current run, incident, connector, dataset, prompt, or approval identity plus origin/provenance.
- The active work region is the third focal point: table scan summaries, selected detail, evidence notebook, or modal/drawer task content depending on the screen.
- Do not let badges, density controls, decorative motion, or secondary metadata visually outrank the page object and active operator task.

At `md` and above (`>=768px`):
- Restore the desktop sidebar grid with the existing `DashboardNav` IA groups.
- Keep desktop topbar command palette and theme controls.

Mobile nav drawer:
- Opened by `Menu`; renders the existing `ScoriaWeb.DashboardNav` Operate / Improve / Configure groups and active state.
- Must not create a second mobile navigation source of truth.
- Requires scrim click dismiss, Escape dismiss, focus containment, focus restore to `Menu`, scrollable nav body, and visible close control.
- Motion is edge-origin slide/fade, 200ms max, transform/opacity only.
- Do not use horizontal nav, bottom nav, or command-palette-only navigation.

### Tables and Scan Surfaces

`ScoriaWeb.UI.table/1` is the central contract:
- Add a default `.scoria-table__viewport` or equivalent scroll container around real `<table>` markup.
- Preserve real table semantics on desktop.
- Sticky headers, action columns, row selection, and focus states must work inside the scroll container.
- Table viewports must be keyboard reachable when horizontal scrolling is required.
- Selected rows use both structure (`aria-selected` or `aria-current`) and visible text/badges/labels, not color alone.

Opt-in mobile summaries:
- Add a summary slot/API only for scan-heavy object tables.
- Summary cards/rows expose object label, status badge text, one key scalar/time, and a primary action.
- Use mobile summaries for Runs, Review Queue, Connectors, Dataset Builder, and comparable object-picking surfaces.
- Dense comparison/detail tables keep honest overflow or object-detail stacks instead of fake card conversion.

Workflow and evidence mobile layout:
- Workflow show stacks as object header, next-step verbs, trace/span list, selected detail, then evidence notebook stack.
- Notebook/evidence primitives remain the visual shell for evidence. Do not invent a separate mobile evidence app.
- Unsupported utilities such as `sm:grid-cols-*` and arbitrary `lg:grid-cols-[...]` / `xl:grid-cols-[...]` must be replaced with named Scoria component classes or added as general token-backed utilities only when broadly reusable.

### Motion

Motion source of truth:
- `assets/css/05-motion.css` is the only home for keyframes and named motion primitives.
- New one-off `@keyframes` in LiveViews, components, or inline styles are out of bounds.

Allowed interaction motion:
- User-triggered motion duration: 200ms max.
- Preferred durations: scrim 100ms, command/toast fade 100-120ms, modal pop 150ms, drawer slide/fade 200ms.
- Animated properties for user-triggered motion: opacity and transform only.
- Hover/active affordances may use short color, border, shadow, and tiny active press changes, but no route/page-load cascades.

Allowlisted state indicators:
- Skeleton pulse: opacity-only, no shimmer, no transform, static under `prefers-reduced-motion`, replaced when content resolves.
- Approval/attention cue: finite maximum two cycles, urgent operator attention only, paired with explanatory text, static under reduced motion.

Prohibited:
- `transition: all`
- Infinite attention loops
- Fire, sparkle, lava, bounce, spring, or decorative motion
- Animating width, height, left, right, grid columns, or other layout properties
- Row translate hover effects on dense tables
- JS-owned choreography beyond keyboard/focus behavior and short hidden-delay coordination

Reduced motion:
- `prefers-reduced-motion: reduce` must collapse transitions/animations to effectively instant and keep scrolling behavior non-animated.
- Browser checks must cover at least one modal/drawer path and one skeleton or attention cue.

### Focus, Status, and Accessibility

Focus:
- Preserve `.scoria-root :where(:focus-visible)` as the global baseline.
- Every interactive element must show a visible focus indicator in light and dark themes.
- Focus rings must not be clipped by table/evidence overflow containers.
- Mobile drawer and command palette must trap focus while open and restore focus after close.

Status:
- Badges, selected rows, table sort, nav active state, trace rails, approval highlights, and evidence outcomes require visible text, icon, ARIA state, or structure in addition to tone color.
- Sort buttons/headers must expose direction with both visible indicator and accessible text or state.
- Current page nav uses `aria-current="page"`.
- Selected list/table/options use `aria-selected` or an equivalent semantic state where appropriate.

Contrast:
- Body text: WCAG AA 4.5:1 minimum in both themes.
- Large text: WCAG AA 3:1 minimum in both themes.
- Non-text UI indicators, borders that define controls, and focus rings: 3:1 minimum against adjacent colors.

## Copywriting Contract

New Phase 16 copy is expected only for the mobile nav drawer, table mobile summaries, smoke-test fixtures if visible, and error/fallback states touched by responsive work.

| Element | Copy |
|---------|------|
| Primary CTA | `Open trace` for run summaries; `Inspect connector` for connector summaries; `Open dataset` for dataset summaries; use the existing domain verb plus noun where a table already has one |
| Mobile nav open | `Menu` with `aria-label="Open navigation"` |
| Mobile nav close | `Close navigation` |
| Empty state heading | Use domain-specific headings for touched surfaces: `No runs match this view`, `No review candidates match this view`, `No connectors match this view`, `No datasets match this view`, `No approvals match this view`; fallback for any other touched table is `No matching records yet` |
| Empty state body | `Adjust your filters or check back when data is available.` unless the parent screen already has sharper domain copy |
| Error state | `This view could not render responsively. Use the table scroll area or widen the viewport, then try again.` only for developer/test-visible fallback; avoid shipping this to normal users unless a real failure path exists |
| Destructive confirmation | No new destructive actions in Phase 16. Existing destructive/decision modals keep their current confirmation copy and danger styling. |

Tone:
- Calm, exact, useful.
- Prefer operator evidence verbs: Open, Inspect, Review, Promote, Retry, Approve, Reject.
- Avoid hype, magic language, decorative motion language, and hidden-chain-of-thought phrasing.
