<objective>
Centralize table responsiveness in `ScoriaWeb.UI.table/1` (D-07). Add a default horizontal-scroll viewport around the real `<table>` so wide tables stay usable at 375px, keep desktop table semantics intact (D-09), and add an opt-in per-row `mobile_summary` slot (D-08) for scan-heavy object-picking tables. Because the responsive behavior lives in the shared component, shared tables do not need bespoke per-screen mobile forks — per D-14 those forks stay reserved for true object inspectors where the shared component genuinely cannot express the layout. Ensure sticky headers, action columns, and row selection still work inside the scroll container, the viewport is keyboard reachable, and selection/sort state carry structure + text (not color alone) per D-13/D-24/MOTION-02.

Purpose: One component change pays dividends across every table screen (Runs, Review Queue, Connectors, Dataset Builder, Eval, Prompt, Approvals) — the highest-leverage responsive fix. Implements the Tables and Scan Surfaces section of the UI design contract.
Output: Extended `table/1` API, `.scoria-table__viewport` + mobile-summary CSS, and component tests.
</objective>
