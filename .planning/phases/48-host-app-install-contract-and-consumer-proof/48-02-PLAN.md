<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Repo test process -> generated temp host | The repo shells into a generated app and must not leak or corrupt state outside the temp harness |
| Generated host -> local dependency source | The proof depends on deterministic local repo contents rather than a checked-in sample app or flaky network transport |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-48-02-01 | Tampering | generated host overlay and temp paths | mitigate | Create the host under a unique temp directory, copy only a tiny overlay, and clean it up with `on_exit`. |
| T-48-02-02 | Information Disclosure | temp harness database/config | mitigate | Assign a unique generated-host DB name and keep host-specific config inside the temp app rather than reusing repo-local DB state. |
| T-48-02-03 | Repudiation | host-proof command orchestration | mitigate | Run each host step explicitly with captured stdout/stderr and fail on the first non-zero status so partial install/migrate success cannot be misreported. |
</threat_model>
