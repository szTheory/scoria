<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| orchestrator result -> eval persistence | Runtime execution outcomes become durable operator-visible provenance |
| ETS breaker state -> dashboard projection | Process-local health data is transformed into operator-facing health rows |
| worker completion -> PubSub | Durable rollup transitions fan out to live dashboard subscribers |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-34-01 | Tampering | fallback provenance fields | mitigate | Persist `resolved_provider`, `resolved_model`, and `fallback_used` from the traced orchestrator result rather than trusting UI inference or worker-envelope guesses. |
| T-34-02 | Information Disclosure | model-health projection | mitigate | Build health rows from explicit provider:model ids already used by Scoria, and keep tenant-scoped PubSub topics so one tenant's dashboard cannot subscribe to another tenant's projection feed. |
| T-34-03 | Denial of Service | PubSub refresh spam | mitigate | Broadcast only after durable rollup transitions and reuse summary/detail query APIs instead of pushing large payloads over PubSub. |
| T-34-04 | Tampering | provenance migration | mitigate | Block later UI work on a real migrate/rollback/migrate cycle so the dashboard cannot depend on phantom schema fields. |
</threat_model>
