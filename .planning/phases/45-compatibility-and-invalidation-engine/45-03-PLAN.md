<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Compatibility drift -> entry lifecycle state | Prompt, policy, and source changes can revoke reuse eligibility across existing rows |
| Invalidation fan-out -> durable cache truth | Bulk transitions must change only the intended tenant/lane slice and must remain auditable |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-45-03-01 | Tampering | invalidation fan-out | mitigate | Scope bulk invalidation queries by tenant and lane compatibility slice before `update_all`, then append one event per changed row. |
| T-45-03-02 | Information Disclosure | stale vs invalidated handling | mitigate | Keep `stale` separate from `invalidated` so age decay cannot mask provable incompatibility or widen reuse later. |
| T-45-03-03 | Spoofing | operator/manual revoke path | mitigate | Require explicit `revoke_entry/2` calls that set `operator_revoked` rather than overloading generic invalidation helpers. |
| T-45-03-04 | Repudiation | semantic reuse correctness | mitigate | Every stale or invalidated transition records a stable reason code and event lineage before runtime fallthrough continues. |
</threat_model>
