<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Runtime metadata -> semantic outcome state | Public runtime inputs become operator-visible lookup decisions |
| Lookup outcome -> workflow continuation | Cache results can either short-circuit to a hit or continue into the normal execution path |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-45-02-01 | Spoofing | actor scope narrowing | mitigate | Persist candidate tenant/actor/scope facts on hit or reject so actor-scoped history cannot silently widen into tenant-shared reuse. |
| T-45-02-02 | Tampering | fallback truth | mitigate | Use explicit `lookup_status` values `bypass`, `miss`, `reject`, and `hit`, and continue through the existing workflow path on miss or reject. |
| T-45-02-03 | Information Disclosure | semantic result reuse | mitigate | Admit future reusable rows only after writeback computes the same prompt/policy/source compatibility fields used by lookup. |
| T-45-02-04 | Repudiation | runtime outcome explanation | mitigate | Store `eligibility_reason_code` only for pre-lookup bypasses and `lookup_reason_code` only for post-candidate rejects, preserving support-truth semantics. |
</threat_model>
