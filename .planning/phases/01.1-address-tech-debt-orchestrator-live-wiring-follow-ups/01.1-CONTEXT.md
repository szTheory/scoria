<decisions>
## Implementation Decisions

### Phase scope triage (D-132)

- **D-132:** Phase 01.1 is a **surgical hardening slice** — not a feature phase. Three plan waves (redaction → approval E2E → token delta proof). Milestone audit items mapped: IN = redaction gaps, approval E2E gap, token delta test; OUT = UAT, UI stubs, ReqLLM streaming, Observe startup code change, legacy shim removal.

### Redaction defense-in-depth (D-133–D-134)

- **D-133:** Apply **`Redactor.redact/1`** in `Scoria.Observe.Telemetry.handle_event/4` for `[:scoria, :observe, :span, :delta]` **before** `OperatorBroadcast.span_delta/1` — mirror span-stop ordering (D-118: redact → broadcast → buffer). Chunk text on PubSub must never bypass scrubbing.
- **D-134:** In `OrchestratorLive.span_view_from_record/1`, run **`Redactor.redact/1`** on span attributes (or full span map) before `TraceProjection.span_view/1`. Defense in depth for legacy/manually inserted DB rows on reconnect hydrate — normal telemetry path already persists redacted attributes.

**Tests:** Extend `telemetry_test.exs` for delta redaction; add hydrate test asserting deny-list keys never appear in `attributes_preview` after reconnect.

### Approval decision integration proof (D-135–D-137)

- **D-135:** Add integration test(s) in `orchestrator_live_integration_test.exs` proving **approve happy path** without `send/2`: `Runtime.start_run` → real `wait_for_approval` handler → modal visible → **click Approve** → modal clears, inbox reflects decision, no raw secrets in DOM.
- **D-136:** Add **reject path** integration test: Reject → modal clears, run stays `waiting_for_approval` / no `Resume.resume_run/1`, durable rejection copy preserved (D-124).
- **D-137:** Keep existing `orchestrator_live_test.exs` `send/2` tests as **UI unit tier**. Do not remove. Semantic fast-path pin unchanged; do not add to `closeout_order/0`.

**Idiomatic pattern:** Producer path via workflow handlers + `Workflows.approve/3` + `OperatorBroadcast.approval_decided/3` — same trust model as LangGraph interrupt + Temporal signal + GitHub stale-review UX already wired in Phase 01.

### Token delta path — test + polish, not streaming (D-138–D-141)

- **D-138:** **Do not** ship ReqLLM streaming adapter in 01.1. Full adapter remains v2.12+ (D-125/D-128).
- **D-139:** Introduce **`Scoria.Observe.Telemetry.emit_span_delta/1`** — public API wrapping `:telemetry.execute([:scoria, :observe, :span, :delta], ...)`. Future ReqLLM streaming adapter calls this; integration tests use workflow handler calling this API (avoids forbidden raw `:telemetry.execute` in test file per D-129 spirit).
- **D-140:** Integration test: workflow handler emits deltas during `Runtime.start_run/2` → assert coalesced **`token_previews`** on active LLM span row in trace tree (75ms coalesce, `stream_insert` re-render). Proves `{:trace_delta}` → coalesce → `TraceTreeComponent` path.
- **D-141:** In `maybe_clear_token_preview/2`, **cancel pending `token_timers`** ref via `Process.cancel_timer/1` when span completes (`end_time` set) — prevents stale flush after span stop (01-REVIEW follow-up #3).

### Claude's Discretion

Planner may choose exact test handler names, assertion helpers (`eventually/1` thresholds), and whether approve/reject are one or two test cases — bounded by D-135–D-141. File layout for `emit_span_delta/1` (Telemetry vs small Observe helper module) is planner discretion.
