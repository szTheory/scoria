## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, compact inline metadata, row affordance gaps |
| sm | 8px | Compact element spacing, nav item gaps, badge-to-label spacing |
| md | 16px | Default element spacing, inventory row cell padding, artifact table rhythm |
| lg | 24px | Section padding, grouped inventory/risk regions, page margins on narrow surfaces |
| xl | 32px | Layout gaps, default dashboard main padding, major artifact sections |
| 2xl | 48px | Major section breaks between baseline proof, inventory taxonomy, and risk register |
| 3xl | 64px | Page-level spacing only when an artifact needs clear separation before appendices |

Exceptions:
- `12px` is allowed only where existing Scoria tokens already use `--scoria-space-3` for dense dashboard chrome.
- `44px` minimum touch target is required for icon-only buttons, mobile topbar controls, drawer close controls, and any future inventory-lab affordance.
- `96px` exists as `--scoria-space-9` but is not used by Phase 36 artifacts.

Source: `assets/css/02-tokens.css`, `assets/css/04-components.css`, `brandbook/tokens.json`.

## Typography

Use exactly these four UI text sizes and two weights for Phase 36 artifact-facing UI, docs screenshots, and any generated inventory preview. Do not introduce additional type sizes in this phase.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 14px | 400 | 1.5 |
| Label | 12px | 600 | 1.5 |
| Heading | 24px | 600 | 1.2 |
| Display | 30px | 600 | 1.2 |

Rules:
- Use `400` for explanatory prose, table body text, evidence notes, and risk descriptions.
- Use `600` for headings, table headers, labels, badges, primary row names, and status emphasis.
- Use `JetBrains Mono` only for stable IDs, file paths, route names, component names, hooks, commit hashes, trace IDs, JSON keys, and code/evidence blocks.
- Letter spacing remains `0` for normal text. Existing uppercase eyebrow labels may use `--scoria-tracking-eyebrow` only when already part of Scoria component vocabulary.

Source: `assets/css/02-tokens.css`, `assets/css/03-base.css`, `brandbook/tokens.json`.

## Color

Use semantic Scoria tokens, not raw palette values, in implementation. Hex values below identify the canonical light/dark semantic endpoints.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | dark `--scoria-surface-app` `#11100f`; light `--scoria-surface-app` `#faf5ef` | App background, artifact canvas, baseline proof background |
| Secondary (30%) | dark `--scoria-surface-panel` `#181513`; light `--scoria-surface-panel` `#fff9f3` | Panels, sidebars, nav, inventory table/list containers, risk register regions |
| Accent (10%) | dark `--scoria-action` `#e65a32`; light `--scoria-action` `#b94f31` | Primary action, current nav indicator, focus-adjacent brand emphasis, selected classification owner, links that move the maintainer to evidence |
| Destructive | dark `--scoria-danger-action` `#ff6b4a`; light `--scoria-danger-action` `#9e2f20` | Destructive actions only; Phase 36 has none by default |

Accent reserved for: primary artifact action (`Open inventory` if a preview route exists), active/current navigation state, focused actionable controls through `--scoria-focus-ring`, selected canonical owner emphasis, evidence links, and brand mark usage. Accent is not a general decoration color and must not be used for every interactive element.

Status colors:
- `--scoria-tone-pass-*` for canonical/proven rows.
- `--scoria-tone-info-*` for intentionally page-specific rows and neutral guidance.
- `--scoria-tone-warn-*` for duplicated, missing, or unproven rows.
- `--scoria-tone-fail-*` for legacy rows with active migration risk or failed proof.
- `--scoria-tone-trace-*` for trace/evidence-specific metadata only.

Source: `assets/css/02-tokens.css`, `brandbook/tokens.json`, `.planning/phases/36-baseline-and-inventory/36-CONTEXT.md` D-18 through D-20.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | `Open inventory` |
| Empty state heading | `No inventory rows found` |
| Empty state body | `Run the Phase 36 inventory scan before planning later UI work.` |
| Error state | `Inventory source scan failed. Check the listed paths, rerun the existing proof commands, and update the risk register before continuing.` |
| Destructive confirmation | none — Phase 36 must not delete source files, remove routes, change UI behavior, or discard proof artifacts |

Copy rules:
- Use operator and maintainer job language first: `inventory`, `baseline`, `evidence`, `risk`, `owner phase`, `next action`.
- Keep implementation nouns available as evidence, not primary orientation: file paths, routes, component names, hooks, commit hashes, tests, and payloads belong in evidence columns, details, or monospace rows.
- Use stable IDs exactly as declared in context and research: `RISK-V30-PROOF`, `RISK-TOAST-LEGIBILITY`, `RISK-APPROVAL-HISTORY`, `RISK-RESPONSIVE-SCAN`, `RISK-OVERLAY-FOCUS`.
- Do not imply that Phase 36 fixes approval toast legibility, implements approval decision history, adds a runtime lab, or creates screenshot-diff CI.

Source: `.planning/phases/36-baseline-and-inventory/36-CONTEXT.md` D-01 through D-28; `.planning/REQUIREMENTS.md` BASE-01, INV-01, INV-02.

## Phase 36 Visual And Interaction Contract

Phase 36 produces inventory artifacts, not a redesigned runtime surface. If implementation creates any preview, generated doc table, or maintainer-facing local page, it must follow this contract:

| Surface | Contract |
|---------|----------|
| Baseline proof summary | Show git provenance, existing ExUnit/Playwright proof, and advisory screenshot evidence as separate sections. Screenshot evidence is labeled advisory, not a CI gate. |
| Inventory rows | Every row visually exposes `id`, `name`, `layer`, `status`, `owner_path`, `evidence`, `replacement_or_owner`, `next_action`, and `risk_refs`. Do not hide required fields behind hover-only UI. |
| Classification status | Render `canonical`, `duplicated`, `legacy`, `missing`, and `intentionally-page-specific` as text plus tone, never color alone. |
| Layer taxonomy | Render `foundation`, `primitive`, `component-group`, `page`, `hook`, `fixture`, `test`, `doc`, and `one-off` consistently across Markdown and structured index references. |
| Risk register | Use a central risk section with stable risk IDs and per-row `risk_refs`; do not duplicate long risk prose inside each row. |
| Evidence disclosure | Keep paths, tests, routes, hooks, and commits visible or one click away. Raw evidence/code blocks use mono text, copy affordances, and existing raw-evidence styling. |
| Responsive behavior | Tables must have a mobile summary/list path at `<768px`; no essential inventory fields may be available only in a wide desktop table. |
| Keyboard behavior | Links, copy controls, disclosures, and any generated filters are reachable by keyboard with visible focus and predictable tab order. |
| Motion | Use existing `100ms`, `150ms`, and `200ms` transform/opacity token patterns only. Respect `prefers-reduced-motion`. No decorative animation. |

No implementation phase may start from a UI-SPEC interpretation that changes runtime `/scoria` UI styling or behavior during Phase 36 unless the change is strictly required to generate or inspect the inventory.
