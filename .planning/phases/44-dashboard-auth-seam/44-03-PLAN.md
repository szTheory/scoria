<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser URL -> approval selection | Public approval IDs and filters select UI candidates only after tenant-scoped lookup. |
| LiveView action -> Workflows decision API | Approval decisions cross from dashboard UI into write-side workflow code. |
| PubSub -> approvals page | Tenant-specific updates may reveal pending approvals if topic is spoofed. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-44-03-S | Spoofing | `ApprovalsLive.Index.mount/3` | mitigate | Use `socket.assigns.tenant_id` from DashboardScope only. |
| T-44-03-I | Information Disclosure | approval drawer deep links | mitigate | Keep tenant-scoped approval resolution and add cross-tenant tests. |
| T-44-03-T | Tampering | approve/deny action context | mitigate | Build tenant/actor audit context from asserted scope, not from public params or hardcoded defaults. |
| T-44-03-E | Elevation of Privilege | approval decision writes | mitigate | Host authz remains delegated; Scoria refuses missing scope and writes only under asserted tenant. |
