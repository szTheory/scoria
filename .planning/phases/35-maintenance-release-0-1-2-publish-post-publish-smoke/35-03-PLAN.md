## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| GitHub Actions -> Hex.pm | Release workflow can publish immutable public artifacts. |
| Hex.pm registry -> generated host smoke | Live package metadata and tarball contents cross into generated Phoenix consumer apps. |
| Failure diagnosis -> recovery mutation | Recovery decisions may trigger another publish workflow and must be state-gated. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-35-06 | Tampering | Hex publish recovery | mitigate | Do not run local `mix hex.publish`; use existing workflows and exact `0.1.2` inputs only after classification. |
| T-35-07 | Repudiation | Post-publish proof | mitigate | Record release run URL, Hex lookup output, smoke run URL, and recovery branch taken. |
| T-35-08 | Denial of Service | Blind duplicate publish/recovery | mitigate | If target version is visible and smoke failure is transient, rerun only the smoke workflow; if artifact proof fails, stop. |
| T-35-SC | Tampering | npm/pip/cargo installs | accept | No npm/pip/cargo install tasks are introduced. Existing Mix/Hex release commands are already in workflows. |
</threat_model>
