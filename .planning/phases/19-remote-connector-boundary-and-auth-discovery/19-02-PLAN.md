<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| host-facing connector API → params seam | Registration input from app code must normalize before persistence |
| params/service layer → discovery jobs | Request-thread work hands off to durable jobs with no hidden transport side effects |
| discovery transport → capability snapshot truth | Remote metadata and catalog data cross from untrusted remote systems into durable local state |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-19-02-01 | S | `Scoria.Connectors.Params` | mitigate | Normalize and validate endpoint, transport, auth, tenant, and metadata fields before service writes per D-02 and D-25. |
| T-19-02-02 | T | registration/update transactions | mitigate | Use `Ecto.Multi` so connector truth and any side-effect triggers stay consistent with durable writes. |
| T-19-02-03 | R | discovery triggers | mitigate | Persist explicit trigger cause and enqueue durable Oban jobs so refresh history is attributable and observable. |
| T-19-02-04 | I | host request/UI code | mitigate | Keep discovery/auth logic behind `Scoria.Connectors` and jobs; do not expose protocol plumbing to LiveView or arbitrary controllers. |
| T-19-02-05 | D | repeated syncs | mitigate | Deduplicate connector refresh jobs by connector and trigger class and record failure status instead of blind retries. |
| T-19-02-06 | E | policy/identity creep | accept | Stable tool identity and dual-plane policy enforcement remain deferred to Phase 20 and must not be partially implemented here. |
</threat_model>
