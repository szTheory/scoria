<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser session → Scoria auth callback | Transient OAuth state crosses from user-agent redirects into Scoria-owned callback handling |
| remote auth server → durable grant rows | Tokens and grant metadata enter local durable storage from an external provider |
| auth completion → post-auth refresh job | Successful auth must trigger explicit durable refresh work without request-thread transport leakage |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-19-03-01 | S | auth callback state | mitigate | Store short-lived `state` and PKCE verifier in session only and reject invalid or replayed callback state per D-17. |
| T-19-03-02 | T | grant completion writes | mitigate | Persist grant truth through normalized service functions with optimistic locking and explicit status/error updates per D-21. |
| T-19-03-03 | R | auth success/failure evidence | mitigate | Create redacted audit events for auth start, success, and failure via `Scoria.SRE`; never rely on implicit transport logs alone. |
| T-19-03-04 | I | tokens and client secrets | mitigate | Encrypt secret-bearing fields at rest and keep them out of cookies, router params, and audit metadata per D-17 and D-20. |
| T-19-03-05 | D | request-thread discovery/auth work | mitigate | Redirect/callback handlers delegate transport and post-auth refresh to services/jobs instead of doing catalog sync inline. |
| T-19-03-06 | E | scope escalation / policy / approvals | accept | Dual-plane policy, stable tool identity, approvals UX, and full operator evidence UX are explicitly deferred to Phases 20-22. |
</threat_model>
