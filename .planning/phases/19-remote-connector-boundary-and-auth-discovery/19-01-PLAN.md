<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| host app input → connector persistence | Untrusted registration/auth metadata crosses into durable Scoria-owned rows |
| durable grant rows → operator evidence | Secret-bearing fields must never leak into queryable metadata or audit refs |
| runtime trigger → background sync job | Connector refresh must leave request/UI paths and become explicit durable work |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-19-01-01 | S | connector/grant tables | mitigate | Keep connector identity, grant subject, and status as first-class durable columns with unique keys and optimistic locks per D-05 through D-08. |
| T-19-01-02 | T | encrypted grant secrets | mitigate | Use `CloakEcto` via `Scoria.Vault`; never store raw access tokens or client secrets in plain map fields per D-20. |
| T-19-01-03 | R | job execution truth | mitigate | Use Oban-backed durable jobs so discovery/refresh triggers have inspectable rows instead of fire-and-forget tasks per D-10. |
| T-19-01-04 | I | operator-visible metadata | mitigate | Separate secret-bearing fields from queryable scope/expiry metadata and keep bounded redacted maps only for low-risk details. |
| T-19-01-05 | D | hidden polling loops | mitigate | Explicitly reject periodic polling defaults; only explicit trigger-driven jobs are in scope per D-10 and D-11. |
| T-19-01-06 | E | future connector invocation path | accept | Stable tool identity and dual-plane policy are deferred to Phase 20 and must not be backfilled here. |
