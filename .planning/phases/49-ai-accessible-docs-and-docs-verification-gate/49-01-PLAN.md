<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| public docs -> adopters and AI readers | Public root docs can influence humans and agents that copy instructions into real projects. |
| generated docs -> source docs | Generated `doc/` output looks source-like but is ignored build output and must not become the edit target. |
| repo agent guidance -> source tree | `AGENTS.md` can steer coding agents to edit, run commands, or expose internal paths. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-49-01-I | Information Disclosure | `llms.txt`, `AGENTS.md` | mitigate | Contract-test D-10 by blocking planning-only, prompt-corpus, dev-only, and internal-first primary links in root AI docs. |
| T-49-01-T | Tampering | `AGENTS.md` generated-file guidance | mitigate | Require D-06/D-07/D-08 source/generated boundary fragments that instruct agents to edit README/guides/tests, not `doc/` output. |
| T-49-01-S | Spoofing | public AI docs copy | mitigate | Require D-22 vocabulary and negative contracts for future-seed overclaims so AI readers do not see unshipped capabilities as current. |
| T-49-01-R | Repudiation | AI docs contract tests | mitigate | Centralize required paths/fragments in `Scoria.AiDocContract` and run focused ExUnit tests with warnings-as-errors. |
| T-49-01-SC | Tampering | package installs | accept | No npm, pip, cargo, Hex, or dependency install task is introduced by this plan. |
</threat_model>
