<objective>
Make the halt visible in the three places an operator actually looks: the trace, the metrics stream,
and the approvals inbox.

The trace half deliberately trips a canary. `test/scoria/observe/semconv_test.exs` pins the attribute
registry's sorted key list under an explicit "we are refusing to widen the enum" charter, so adding
three keys turns it red. That is the mechanism working, not a failure to route around — the task that
touches `semconv.ex` updates that assertion in the same commit.

The metrics half emits once per run at its terminal transition, not per check: sizing needs the
distribution of final per-run totals, and a stream of running counters would force every adopter to
build a stateful aggregator keyed by run id, which nobody does, so the events would get filtered out.

The inbox half fixes a real false failure: the dashboard resumes a run AFTER the approval has already
committed, and today its generic error clause tells the operator their approval failed when it was
recorded.

Purpose: RAIL-01 success criterion #1's evidence surface, plus the operator-facing consequences of
`"halted"` being a new status.
Output: three registry keys, the `:observed` event, and one LiveView message clause.
</objective>
