**Three `scoria.rail.*` trace attributes on both rail-denial branches, one `[:scoria, :run, :rail, :observed]` telemetry event per run, and an accurate approvals-inbox toast for a halted run instead of a false "could not record" failure.**

## Accomplishments

- `Semconv.attribute_registry/0` gains exactly three new keys (`scoria.rail.rail` `:enum`, `scoria.rail.limit` `:count`, `scoria.rail.observed` `:count`); the pinned sorted key-list canary in `semconv_test.exs` was updated in the same commit as the registry edit, per D-18's explicit "the canary going red is the mechanism working" instruction. `Semconv.rail_attributes/1` is a fixed three-key projector mirroring `trust_attributes/1` — no host-map spread, so an extra key on the input never rides onto a span.
- `Runtime.execute_step/2`'s **both** rail-denial branches (the `max_active_ms` pure-Elixir pre-check from plan 56.1-04, and `Rails.admit_step/2`'s `max_steps` atomic CAS from plan 56.1-01) now add `attributes: Semconv.rail_attributes(...)` to `span_opts` before `Observe.span/4` opens; the admit path adds no `:attributes` key at all. No second span, no guardrail span (Phase 55 D-21 holds) — proven by asserting the trace's span count stays at exactly 1 for a denied step.
- `Scoria.Workflows.maybe_emit_rail_observed/1` fires `[:scoria, :run, :rail, :observed]` exactly once per run at its terminal transition (`"completed"`, `"failed"`, `"halted"`), called post-commit from the three — and only three — functions that write a terminal run status: `complete_step/3`, `fail_step/3`, `halt_run/3`. Each of the first two callers captures whether its freshly-read `%Run{}` arrived **already** terminal (the same G4/G5 clamp interleaving 56.1-01 documented — a sibling reading the run after a halt already committed) and skips the emit in that case, so a halt followed by a sibling completing against the already-halted row still emits exactly one `:observed` event, not two. `halt_run/3` needs no such guard since it already rolls back to `{:error, :already_halted}` on any second call. Measurements separate `steps`, `tool_calls`, `active_ms`, `paused_ms`, and `wall_ms` as five distinct numbers; metadata carries `run_id`, `tenant_id`, `terminal_status`, `tripped`, the three `max_*` limits, and `site`. Wrapped in `try/rescue -> :ok`.
- The approvals inbox no longer reports a false failure for a decision that was in fact recorded: `maybe_resume_approval/3` now returns a 3-tuple carrying a resume-outcome atom (`:resumed | :not_resumable | :not_applicable`); a run halted by a per-run rail falls through `Workflows.resume_run/1`'s catch-all as `{:error, :not_resumable}`, and `record_approval_decision/2` picks an accurate info-tone toast instead of either the misleading "Approval granted." copy or the generic "Could not record ... approval decision" failure branch. `approval_error_message/2` gains a dedicated `:not_resumable` clause positioned above the generic fallback, alongside the existing `%Ecto.StaleEntryError{}` clause it mirrors.
- `Scoria.Web.UI.tone/1`'s `:fail` clause list gains `"halted"` (the second D-01 follow-on), with a dedicated unit test asserting `tone("halted") == :fail`.
