<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| replay run -> connector invocation | untrusted replay inputs could otherwise escape into live remote traffic |
| replay approval row -> live execution | authority must come from current replay-scoped approval, not historical approval evidence |
| retry loop -> audit/live effect seam | duplicate replays must not duplicate side effects |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-38-05 | E | `Scoria.Workflows.request_remote_approval/3` and `approve/3` | mitigate | Remove default `replay_allowed=true`, require replay-scoped approvals, and compare source lineage and argument fingerprint before live replay authority is granted. |
| T-38-06 | T | `Scoria.Connectors.Invocation.invoke/5` and `Scoria.MCP.Executor.execute/4` | mitigate | Run the replay disposition resolver before outbound execution and return `:replay_blocked` when historical evidence is missing or mismatched. |
| T-38-07 | D | live replay retry path | mitigate | Generate and persist a stable `replay_idempotency_key` for any allowlisted live replay so duplicate writes reuse audit dedupe identity. |
| T-38-08 | T | run/approval updates under concurrency | mitigate | Keep optimistic locking on authority rows and add regression tests for stale replay approval updates and conflicting run mutations. |
</threat_model>
