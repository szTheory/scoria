<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| workflow runtime -> durable evidence rows | replay safety decisions cross from in-memory execution into operator-trusted storage |
| historical approval evidence -> replay authority | old approval truth must not become live authority for a new replay branch |
| replay branch -> audit dedupe store | live replay retries must reuse a stable dedupe identity |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-38-01 | E | `ai_approvals` authority fields | mitigate | Add `replay_scope`, `replay_disposition`, source lineage IDs, and `executed_live` so historical approvals are evidence only per D-09 through D-13. |
| T-38-02 | T | checkpoint/event/audit replay evidence | mitigate | Store `replay_disposition` and `replay_reason_code` as typed columns so missing historical evidence cannot be hidden in metadata and later fall through to live traffic. |
| T-38-03 | D | replay-live retry path | mitigate | Add `replay_idempotency_key` and indexed audit dedupe storage so duplicate live replay writes are rejected or coalesced on retry per D-22. |
| T-38-04 | T | approval/run optimistic locking | mitigate | Preserve `optimistic_lock(:lock_version)` on run and approval rows and add plan-02 enforcement that stale concurrent updates must raise instead of overwriting each other. |
</threat_model>
