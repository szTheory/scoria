## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| durable workflow truth -> public runtime DTOs | projection mistakes could hide replay/source lineage or mis-state the source variant being promoted |
| source run lookup -> replay comparison builder | incorrect matching could compare the wrong original evidence to a replay step |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-39-01 | T | `Scoria.Runtime.ReplayComparison` | mitigate | Prefer explicit `source_step_id` and `source_checkpoint_id` from durable metadata before sequence fallback so original/replay matching cannot drift silently. |
| T-39-02 | I | `Scoria.Runtime.RunDetail` | mitigate | Expose only curated `comparison_by_step` and `promotion_snapshot` groups, never raw structs or uncontrolled payload dumps. |
| T-39-03 | R | `Scoria.Runtime.get_run_detail!/1` | mitigate | Preserve `workflow_run_id`, `workflow_step_id`, `source_variant`, and `replay_reason_code` in promotion snapshot fields so later dataset items can prove provenance. |
| T-39-04 | D | replay source lookup | accept | Source run loading adds one extra workflow-tree read for replay runs only; acceptable because Phase 39 stays on operator inspection paths rather than request-path execution. |
</threat_model>
