## Phase Surface Contract

Phase 47 is a text-first documentation UX phase. The primary user interaction is reading and following links in `README.md` and stable `docs/*.md` guides. Do not create a landing page, custom HTML hero, decorative visual, new navigation widget, tabs, accordion, or dashboard component for this phase.

README first screen must use this order:

1. Existing brand mark, `# Scoria`, tagline, and badges.
2. Plain-English embedded-Phoenix product paragraph from Phase 47 D-01.
3. Short roles-not-headcount "who this is for" paragraph.
4. Compact "not for" line or boundary list.
5. Text link or compact preview for "What Scoria owns vs what your app owns."
6. Only after those: capability ladder, install, quickstart, and verification-suite details.

The first-screen contract forbids capability names, verification-suite language, internal milestone vocabulary, or competitor comparisons before the plain-English product paragraph. Links must use descriptive text, not "click here." Tables must stay scannable: short cell text, concrete owner nouns, and any long rationale moved below the table.

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Inline gaps, badge/logo breathing room when existing rendered assets require it |
| sm | 8px | Compact list spacing, table cell breathing room in rendered docs |
| md | 16px | Default paragraph, list, and code-block separation |
| lg | 24px | Section-internal spacing and scope-table intro spacing |
| xl | 32px | README first-screen group break before capability details |
| 2xl | 48px | Major guide section breaks when rendered in Scoria-owned docs surfaces |
| 3xl | 64px | Page-level spacing only; avoid adding this before first-screen content |

Exceptions: Existing Scoria tokens include `--scoria-space-3: 12px`; it is allowed only for dense table/list gaps inherited from current docs styling. Preserve existing 44px touch targets if dashboard chrome is incidentally touched, but Phase 47 must not add new interactive controls.

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 14px | 400 | 1.5 |
| Label | 12px | 600 | 1.45 |
| Heading | 18px | 600 | 1.2 |
| Display | 24px | 600 | 1.2 |

Use exactly these two weights for any Scoria-rendered docs surface: 400 regular and 600 semibold. In Markdown, rely on native heading levels instead of inline HTML or custom sizing. Keep README copy short enough that the opening paragraph scans as one paragraph, not a hero block.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | Native Markdown surface; Scoria fallback `#11100f` dark / `#efe6de` light | Page background and reading surface |
| Secondary (30%) | Native table/code surface; Scoria fallback `#181513` dark / `#fff9f3` light | Tables, code fences, compact callout-like Markdown sections |
| Accent (10%) | `#e65a32` dark / `#b94f31` light | Existing logo mark, links, source citations, and focus ring in Scoria-rendered surfaces |

Accent reserved for: existing brand mark, Markdown links, comparison-guide source links, package/status badges inherited from README, and focus outlines if rendered in Scoria UI. Do not color every capability, persona row, scope row, or warning with the accent.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | Compare boundaries |
| Empty state heading | No adopter guide found |
| Empty state body | Run `mix scoria.release_preview` and check packaged docs before release. |
| Error state | This comparison may be stale. Check the linked source docs and rerun the docs contracts before release. |
| Destructive confirmation | none — Phase 47 has no destructive user action and must not add delete/archive controls |

Voice contract: calm, exact, operator-grade, low hype. Prefer "Scoria owns..." and "Your Phoenix app owns..." over abstract doctrine labels. Treat reviewer as a role one engineer may wear, not a department. Do not claim unbuilt OpenInference export, lethal-trifecta enforcement, deeper eval calibration, retrieval eval depth, retention, masking, purge, or feedback governance.
