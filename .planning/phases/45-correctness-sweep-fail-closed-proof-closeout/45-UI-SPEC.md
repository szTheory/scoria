| Status / Evidence | Required Tone |
|-------------------|---------------|
| `passed` / successful proof | `:pass` badge with visible "Passed" text |

| Raw cosine similarity, latency value, citation count, vector dimension | Neutral metadata treatment; never color-only |

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | Run proof |
| Empty state heading | No evidence recorded |
| Empty state body | Run the proof commands or adjust filters once new evidence is available. |
| Error state | Could not load proof evidence. Refresh and try again. |
| Destructive confirmation | None - Phase 45 adds no destructive action or confirmation UI. |

Copy rules:

- Phase 45 is fix-and-prove only. Do not add a new operator-facing screen, onboarding flow, tenant switcher, scope bar, scope receipt, modal, drawer, or action receipt.
- If existing eval or knowledge UI displays changed evidence, label it as mechanism evidence: `Cosine similarity`, `Latency`, `Citation count`, `Expected answerable`, `Inconclusive`, `Not scored`, `Passed`, or `Failed`.
- Retrieval scores are raw cosine similarity, not probability. Do not label them "confidence", "match percent", "quality", or "safe".
- Missing configured latency evidence must read as `Inconclusive` or `Not recorded`; never display `0 ms` unless the value was actually measured.
- Browser-facing copy must not reveal tenant IDs, foreign-object existence, resolver internals, query vectors, raw embeddings, or host policy details.
- Voice remains calm, exact, and useful. Do not use "magic", "seamless", "nothing here", "probably", or "confidence" for these proof surfaces.

## Phase 45 Interaction Contract

### Baseline

- Preserve the existing `/scoria` dashboard shell, navigation groups, page headers, table controls, empty states, overlays, command palette, theme toggle, and responsive behavior.
- Do not add a persistent scope bar, tenant switcher, UI receipt, end-user authorization UI, or new dashboard route. These are explicitly deferred to SEED-013 or later feature seeds.
- Do not introduce a new visible control for FIX-01..04 or DOC-01. The phase is backend correctness, deterministic tests, and narrow docs/proof closeout.
- If an existing UI surface already shows eval, retrieval, grounding, latency, or status evidence, update only the text/status semantics needed to stay honest.

### Measurement Display

- Cosine score display: show raw decimal evidence only when an existing surface already renders retrieval scores. Label it `Cosine similarity`; do not convert to a percent or clamp/round it into a prettier status.
- Latency display: show measured score latency as `{n} ms` only when present and parseable. If the configured latency gate lacks evidence, show `Inconclusive` or `Not recorded`, not `0 ms`.
- Citation display: if `expected_answerable` is visible, render it as a neutral label/value pair (`Expected answerable: Yes/No`) and pair the outcome with a visible status badge.
- Chunker display: do not add overlap controls or copy that implies `Chunker.Default` supports sliding-window overlap. If docs mention it, say `Default chunking is section/paragraph based and non-overlapping`.

### Fail-Closed States

- Missing, unknown, or unparseable measurement evidence must be visually warning-grade (`:warn`) and textually explicit (`Inconclusive` or `Not scored`).
- Failed proof must be failure-grade (`:fail`) and explain the next operator action with existing error copy patterns.
- Successful proof must be pass-grade (`:pass`) only when persisted evidence is actually passing; do not use green for "no error thrown".

### Documentation Touches

- DOC-01 cross-links are documentation/proof content, not a new UI information architecture.
- Cross-link copy should explain why the mechanism is Scoria-owned and the noun/policy remains host-owned.
- Do not write the full owns-vs-delegates table in this phase; SEED-005 owns the stable docs front door.

| Panels | `panel/1` / `.scoria-panel`; no nested cards |

No new raw hex, RGB/HSL values, Tailwind palette class, one-off selector, layout shell, card system, icon library, typography class, or frontend dependency may be introduced for this phase. Any asset CSS change must be rebuilt into `priv/static/scoria/app.css` with the existing asset build path.

## Accessibility Contract

- All statuses must include visible text and must not rely on color alone.
- Static empty states should not use `role="alert"`. Use alert semantics only for actual flash/banner failures.
- Icon-only controls keep accessible names. Phase 45 should not add new icon-only controls.
- All focus indicators use `--scoria-focus-ring`; never suppress focus styles.
- Existing mobile controls preserve the 44px minimum hit target, and small controls preserve the 24px minimum target.
- Text must meet the existing WCAG AA token constraints. Do not use `--scoria-text-subtle` for body copy, proof explanations, or failure details.
- Numeric evidence must remain readable in dark and light themes and must not truncate in a way that hides the actual score, latency, or status without an accessible full label.
