<planner_decisions>
Decisions this planner made that CONTEXT.md left open. Each is named so it cannot become an accidental omission.

**D-A1 — `classification/0` isolation: bounded Task, not bare `try/catch`.** RESEARCH.md assumption A1 is a genuine open decision; CONTEXT.md open question 4 speculated bare `try/catch` "should be" enough because `classification/0` is contractually pure, but the precedent it cited (Phase 55 D-20) actually shipped bounded `Task.Supervisor.async_nolink` + internal `try/catch` + `Task.yield`/`Task.shutdown` at `lib/scoria/trust/scan.ex:94-111`. **Decision: follow the precedent.** Rationale: (a) bare `try/rescue` in the caller process does not protect against a hanging/blocking callback — only against raises and throws; (b) the call is memoized once per tool module in `:persistent_term`, so the heavier pattern costs one bounded Task per module for the process lifetime, not per call; (c) `Scoria.MCP.TaskSupervisor` already exists and is already started at `lib/scoria/application.ex:18`, so no new supervisor child and no `application.ex` edit is required. Reversibility: `reversible` — the isolation strategy is entirely private to `Classification.tool_declaration/1`; swapping it later is a local change behind a stable function.

**D-A2 — "consume" means read-side, declared-only.** D-05 says five fail-open sites must *consume* the resolved classification, while D-03 hard-prohibits writing resolved values into `:policy_sensitive`, `:sensitive_tool`, `:approval_sensitive`, `:local_classification`, `:action_class`, or `:risk_level`. These reconcile exactly one way: every site reads the resolved classification from the NEW `:tool_classification` key as an additional, parallel input, and every predicate widened by it is widened **declared-only** — a classification whose `source` is `:unclassified_default` is never an operand (D-04's own law). Consequence, stated plainly: for 100% of traffic that exists today (no tool declares anything yet) every one of the five sites is byte-identical in behavior, and the only phase-56 behavior change available to an adopter is the opt-in `require_tool_classification` refusal (plan 56-02). That is the CLASS-02 "fail-closed-but-inspectable" contract, and it is the same shape `Scoria.Runtime.ReleaseGate`'s `require_eval_verdict` already ships.

**D-A3 — `use Scoria.MCP.Tool` opt defaults are conservative, not maximal.** Unspecified macro opts default to `reads_private_data: false`, `sees_untrusted_content: false`, `can_exfiltrate: false`, `action_class: "read"`. Rationale: the maximal default is reserved for the *absence* of a declaration (D-03's `:unclassified_default`); a tool author writing `use Scoria.MCP.Tool` is making a positive statement, and defaulting their unspecified legs to `true` would make the macro useless (every declaring tool would resolve `admin`). Mirrors `Scoria.SemanticCache.Profile.__using__/1`'s permissive `Keyword.get/3` defaults. Reversibility: `costly` — these are published macro opt names on a public behaviour.

**D-A4 — a hand-written `classification/0` cannot self-assign `source`.** `tool_declaration/1` normalizes whatever the callback returns and forces `source: :tool_declared`. A tool may not claim `:unclassified_default` or `:host_tightened`; a non-struct, junk-`action_class`, or non-boolean-leg return fails closed. Reversibility: `reversible`.
</planner_decisions>
