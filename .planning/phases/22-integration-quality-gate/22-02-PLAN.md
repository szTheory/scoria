<read_first>
Read these BEFORE writing the gate script. The exit-code and output contracts of each existing tool are load-bearing.

- `brandbook/tools/contrast-check.mjs` — CRITICAL: this script has NO `process.exit` and ALWAYS exits 0. It prints a summary line `**Summary:** N pairings — PASS-AA: X · PASS-LARGE: Y · FAIL: Z`. The gate MUST parse the `FAIL: <n>` count from stdout (PASS only when FAIL is 0); do NOT rely on its exit code.
- `brandbook/tools/verify-logos.mjs` — proper exit codes: `process.exit(0)` when `failures === 0`, else `process.exit(1)`. Run it and trust the exit code. (Covers no-rect, evenodd, favicon size, <500KB budget structurally.)
- `brandbook/tools/check-consistency.mjs` — proper exit codes: `process.exit(0)` on full agreement, `process.exit(1)` on mismatch/read error. Run it and trust the exit code. (4-source hex agreement.)
- `brandbook/index.html` — the standalone offline brand book (~55KB). The gate must confirm zero `http://` / `https://` references (the `xmlns="http://www.w3.org/2000/svg"` namespace declaration is the ONLY allowed exception) and that every `src=` (and `href=` to local files, if any) resolves to a file that exists relative to brandbook/.
- `brandbook/` tree — every file under `brandbook/` EXCLUDING `tools/node_modules/` must have an extension in the allowlist `html|md|json|css|svg|mjs|gitignore|lock` (zero binaries). Note `package-lock.json` ends in `.json` (allowed); `.gitignore` and `*.lock` are allowed. Total `du -sk brandbook/` must be < 500KB (the existing verifier uses the same budget; double-checking here is the gate's job too).
- Node `child_process` (`spawnSync`/`execFileSync`) — use to run the three sibling mjs tools and `mix`. Node v22 is available.
- `22-01-SUMMARY.md` (this phase, wave 1) — confirms `mix test` was run green in 22-01. The gate may either re-spawn `mix test` itself OR document that 22-01 ran it green; CONTEXT §discretion prefers spawning it, but if spawning `mix` from the gate is environment-fragile, documenting the 22-01 run (with the SUMMARY as evidence) is acceptable — make the choice explicit in GATE.md.
</read_first>

  <action>
    Create `brandbook/tools/quality-gate.mjs` — a zero-extra-dependency ESM script that runs every final check, prints one PASS/FAIL line per check, and exits 0 iff all checks pass (else 1). Resolve all paths relative to the script's own dir (`fileURLToPath(import.meta.url)`) so it runs from any cwd. Checks, in order:
    1. CONTRAST — `spawnSync('node', ['contrast-check.mjs'], { cwd: __dir, encoding: 'utf8' })`. PASS only if the stdout matches `FAIL: 0` (parse the `FAIL: <n>` integer from the `**Summary:**` line); FAIL otherwise. Do NOT use the child exit code (contrast-check always exits 0).
    2. VERIFY-LOGOS — `spawnSync('node', ['verify-logos.mjs'], ...)`. PASS iff `status === 0`.
    3. CONSISTENCY — `spawnSync('node', ['check-consistency.mjs'], ...)`. PASS iff `status === 0`.
    4. EXTENSION-ALLOWLIST — walk `brandbook/` recursively, skipping `tools/node_modules/`. Every file must match the allowlist `html|md|json|css|svg|mjs` by extension, OR be named `.gitignore`, OR end in `.lock`. FAIL listing any file that does not match (zero binaries).
    5. BRANDBOOK-SIZE — sum the byte sizes of all files under `brandbook/` (or shell out to `du -sk brandbook` and parse KB). PASS iff total < 500KB (512000 bytes / 500 KB — use the same unit the existing verifier uses; document which in the printed line).
    6. INDEX-OFFLINE — read `brandbook/index.html`: PASS iff it contains zero `http://` or `https://` substrings EXCEPT occurrences inside the SVG xmlns namespace `http://www.w3.org/2000/svg` (strip/ignore those before scanning). Additionally extract every `src="..."` (and any local `href="..."` that is not an in-page `#anchor` and not an external URL) and confirm the referenced file exists relative to `brandbook/`. FAIL listing any unresolved ref or disallowed network ref.
    7. MIX-TEST — per the read_first discretion: either `spawnSync('mix', ['test'], { cwd: <repo root>, ... })` and PASS iff `status === 0`, OR (if spawning mix is fragile in this environment) treat it as documented-passed-in-22-01 and print a clearly-labeled `PASS [MIX-TEST] (verified in 22-01; see 22-01-SUMMARY.md)` line. Whichever path is chosen, print it explicitly so GATE.md can record it.
    Track a `failures` counter; at the end print a summary and `process.exit(failures === 0 ? 0 : 1)`. Match the PASS/FAIL line style of the sibling tools (`PASS  [ID]  msg` / `FAIL  [ID]  msg`) for consistency.
