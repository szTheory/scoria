<objective>
Implement the MCP Server-Sent Events (SSE) boundary to allow external Python and Node runtimes to connect and invoke tools securely.

Purpose: Bridge the gap between a long-lived GET SSE connection process and ephemeral POST requests carrying JSON-RPC messages by using Elixir's native Registry for process routing. The controller must execute requested tools via Scoria.MCP.Executor and stream results back.
Output: Active session registry, MCP controller with chunked streaming loop + execution logic, and a router macro for host integration.
</objective>

<task type="auto" tdd="true">
  <name>Task 2: Implement MCP Controller</name>
  <files>lib/scoria_web/controllers/mcp_controller.ex, test/scoria_web/controllers/mcp_controller_test.exs</files>
  <behavior>
    - GET /sse registers session, sets chunked HTTP headers, and emits an `endpoint` event with the session URI.
    - POST /messages with valid session_id routes the payload to the SSE process and returns 202.
    - SSE process receives payload, parses JSON-RPC via Scoria.MCP.Protocol.parse, delegates to Scoria.MCP.Executor.execute (if valid tool), and streams the JSON-RPC formatted result (via Scoria.MCP.Protocol.format_response/format_error) back to client.
    - POST /messages with invalid session_id returns 404.
  </behavior>
  <action>Create `ScoriaWeb.MCPController`. Use `lib/scoria_web/controllers/connector_auth_controller.ex` as an analog for imports and controller structure (from PATTERNS.md).
1. Implement `sse/2`: Generate a UUID via `Ecto.UUID.generate()`. Register in `Scoria.MCP.SessionRegistry`. Setup conn via `send_chunked(conn, 200)` with `content-type: text/event-stream` and `cache-control: no-cache`. Send initial event `event: endpoint\ndata: /mcp/messages?session_id=<id>\n\n`. Enter recursive `listen_loop(conn)`.
2. Implement `listen_loop(conn)`: Use `receive do` waiting for `{:mcp_message, payload}`. When received, parse the JSON payload and pass it to `Scoria.MCP.Protocol.parse`.
   - On `{:ok, request}`, lookup the tool from the connection assigns (e.g., `conn.assigns[:mcp_tools]`). 
   - If found, validate args via `Scoria.MCP.Validator.validate_args`, execute via `Scoria.MCP.Executor.execute`, and format response/error via `Scoria.MCP.Protocol`.
   - Send the resulting JSON string via `chunk(conn, "data: #{Jason.encode!(result)}\n\n")`.
   - Include a 30_000ms `after` timeout to send a `: keepalive\n\n` chunk to prevent connection drops. Break loop gracefully if client disconnects (`{:error, :closed}`).
3. Implement `messages/2`: Lookup `params["session_id"]` in Registry. If found, `send(pid, {:mcp_message, conn.body_params})` and return `send_resp(conn, 202, "")`. Else, return `send_resp(conn, 404, "Session not found")`.</action>
  <verify>
    <automated>mix test test/scoria_web/controllers/mcp_controller_test.exs</automated>
  </verify>
  <done>Controller correctly bridges POST payloads, executes MCP tools, and streams results to the SSE connection.</done>
</task>
