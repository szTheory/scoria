# Phase 43.1: Fix Full-Suite Failures Blocking Clean Relay Closeout - Context

**Gathered:** 2026-05-24
**Status:** Ready for planning
**Source:** Reconstructed from roadmap, state, prior Phase 43 closeout artifacts, and direct failing test runs

<domain>
## Phase Boundary

Phase `43.1` is an urgent cleanup slice inserted after Relay Phase 43 because the milestone proof lane is green but the repo no longer has a clean default `mix test` baseline. The job is not to widen bounded handoffs, replay, or eval product scope. The job is to remove the currently known full-suite regressions that block a clean Relay closeout record.

This phase owns only the current breakpoints observed on 2026-05-24:
- offline eval replay tests reference a missing `Scoria.Eval.Runner` module
- eval spec persistence no longer rejects mutable alias/default inputs the tests say must stay invalid
- the approval inbox component crashes when pending approvals do not carry connector metadata

The phase ends only when the default suite is green and the Relay closeout artifacts can stop carrying a fresh repo-health exception for these regressions.

</domain>

<decisions>
## Implementation Decisions

### Scope and posture
- **D-01:** Treat `mix test` as the acceptance gate for this inserted closeout phase. Unlike Phase 43, this phase exists specifically to restore the clean full-suite baseline.
- **D-02:** Keep the work narrow. Do not reopen bounded-handoff product scope, delegated evidence design, or unrelated operator UX polish while fixing the blocking regressions.
- **D-03:** Prefer restoring boring executable truth over deleting failing coverage. If a surface is still meant to exist, repair it. If it is no longer supported, replace or retire it only with an explicit, equally strong proof surface in the same wave.

### Eval contract truth
- **D-04:** The eval lane must have one coherent offline replay story. The repo currently contains direct tests for `Scoria.Eval.Runner.run_offline/1` and `assert_dataset/1`; planning must decide whether to restore that module or move the proof onto the supported public Eval surface without weakening coverage.
- **D-05:** Mutable convenience inputs such as `dataset_alias` and `default_judge_model` are not durable eval truth for Relay closeout. The current `create_eval_spec/1` contract should reject them explicitly if the tests continue to assert that rejection.
- **D-06:** Campaign lineage, tenant identity, legacy eval-run compatibility, and dataset/version snapshots remain part of the eval persistence truth and must stay green while fixing the stricter alias rejection behavior.

### Approval inbox truth
- **D-07:** Pending approvals may legitimately lack connector metadata. The approval inbox and Orchestrator LiveView must render that sparse shape safely instead of assuming `connector_label` exists.
- **D-08:** Fixing the crash must preserve the current HITL behavior: approval modal rendering, approve/reject actions, durable audit outbox emission, and run/step status transitions.
- **D-09:** The UI fix should stay within the existing operator dashboard surface. Do not redesign the inbox or add new approval concepts as part of this closeout slice.

### Closeout expectations
- **D-10:** Phase `43.1` is complete only with a fresh passing `mix test` run, not just targeted-file greens.
- **D-11:** Relay closeout artifacts must explicitly record that the milestone no longer depends on the accepted “full-suite failures outside owned lanes” exception for these seams.
- **D-12:** If another unrelated failure appears during the final full-suite pass, classify it explicitly before expanding scope. The phase should absorb only regressions that are genuinely required to restore the default suite.

### the agent's Discretion
- Whether the cleanest eval repair is restoring `Scoria.Eval.Runner` or consolidating tests onto a different supported entrypoint, provided the resulting proof remains explicit and durable.
- Whether the approval inbox fix belongs purely in the component or also needs shaping changes in the LiveView projection, provided sparse approvals render safely and the HITL flow remains intact.
- Exact closeout artifact wording for the final Relay repo-health note, provided it is decisive and linked to the fresh suite run.

</decisions>

<specifics>
## Specific Ideas

- The likely phase shape is one eval repair plan, one approval/HITL repair plan, and one closeout verification plan.
- The fastest wrong move here would be deleting failing tests or weakening assertions to claim a clean suite. The right move is to make the code and the tests agree on one supported truth.
- The approval crash is a nil-shape robustness issue, not a product-shape issue. It should be fixed conservatively.

</specifics>
