## Summary

The repo’s current closeout gap is concrete and narrow. Relay’s canonical adoption proof remains valid, but the default suite is red in three linked seams that now justify an inserted cleanup phase. [VERIFIED: `.planning/phases/43-canonical-adoption-proof-milestone-closeout/43-CONTEXT.md`; `.planning/STATE.md`; local targeted test runs on 2026-05-24]

The eval failures split into two distinct problems. First, `test/scoria/eval/offline_runner_test.exs` still asserts a public `Scoria.Eval.Runner` offline replay contract, but the module does not exist, producing two `UndefinedFunctionError` failures. [VERIFIED: `mix test test/scoria/eval/offline_runner_test.exs --trace` on 2026-05-24; `rg -n "defmodule Scoria\\.Eval\\.Runner" lib test` returned no implementation] Second, `test/scoria/eval/eval_run_persistence_test.exs` expects `Eval.create_eval_spec/1` to reject mutable inputs like `dataset_alias` and `default_judge_model`, but `lib/scoria/eval.ex` currently inserts the spec successfully because those attrs pass through to the changeset path without an explicit guard. [VERIFIED: `mix test test/scoria/eval/eval_run_persistence_test.exs --trace` on 2026-05-24; `lib/scoria/eval.ex`]

The operator UI failures are also precise. `ApprovalInboxComponent` renders `approval.connector_label` directly; the HITL tests send a pending approval map without that key, so LiveView crashes with `KeyError` during both approve and reject flows. [VERIFIED: `mix test test/scoria_web/live/orchestrator_live_test.exs --trace` on 2026-05-24; `lib/scoria_web/components/approval_inbox_component.ex`]

**Primary recommendation:** Plan the work in three waves: repair the eval contract drift, harden the approval inbox/HITL rendering path, then run a real `mix test` closeout pass and update Relay’s milestone artifacts with the clean result. This keeps the inserted phase narrow and lets the final closeout wave absorb any truly new failures without pre-committing to unrelated work. ## Patterns to Reuse

### Pattern 1: Fix contract drift at the public seam, not in tests
Scoria’s stronger milestones have kept proof honest by repairing code and checked docs around one supported public seam instead of weakening assertions. The eval repair should follow that pattern: either restore `Scoria.Eval.Runner` as a supported seam or move the tests to a different supported seam in the same change, but do not silently lower the proof bar. [VERIFIED: existing plan style in `.planning/phases/41-bounded-handoff-contract-safety/41-03-PLAN.md`; current failing eval tests]

### Pattern 2: Nil-safe UI over optional durable fields
Approval records already allow sparse metadata. The UI should treat connector labels as optional decorations, not required truth. The minimal safe pattern is optional access plus rendering fallback, while preserving the stable fields (`tool_name`, `status`, reason, audit-backed actions) that actually drive operator trust. [VERIFIED: `lib/scoria_web/components/approval_inbox_component.ex`; failing HITL tests]

### Pattern 3: Final closeout wave uses real suite evidence
When Scoria uses an inserted cleanup phase to settle repo-health, the last plan should be a real suite pass plus artifact reconciliation, not just “targeted files are green.” That pattern matches why `43.1` exists at all. [INFERENCE from the inserted phase goal and state entry]

## Anti-Patterns to Avoid

- Deleting `offline_runner_test.exs` or weakening its assertions without a replacement supported proof seam.
- Accepting `dataset_alias` or `default_judge_model` as persistent eval spec inputs if the durable contract is meant to stay immutable and pointer-free.
- Treating connector metadata as mandatory in approval rendering.
- Marking the phase complete from targeted-file greens without a fresh `mix test` run.
- Expanding the scope into unrelated warnings, optional knowledge lanes, or new bounded-handoff feature work before the current red seams are closed.
