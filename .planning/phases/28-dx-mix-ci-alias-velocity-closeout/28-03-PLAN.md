<!-- The capture chain and the D-D2 computation contract, exact and load-bearing. -->

Capture chain (the ~19min bottleneck):
  CI ratchet job runs:  MIX_ENV=test mix test --warnings-as-errors test/scoria/warning_inventory/tmp_preflight_test.exs
  tmp_preflight_test.exs (line 33-49) shells out:  System.cmd("mix", ["scoria.warning_ratchet.check"], env: MIX_ENV=test)
  scoria.warning_ratchet.check → WarningInventory.capture_output/0
  capture_output/0 → capture_output_standalone!/0 (standalone path; nested path returns "")
  capture_output_standalone!/0 CURRENTLY runs:  System.cmd("mix", ["do", "compile", "--force", "+", "test"], env: MIX_ENV=test)
    → force-recompiles lib/, compiles ALL test files, RUNS THE ENTIRE SUITE (~19min).

The gate consumer (scoria.warning_ratchet.check):
  filters rows where  row.cluster_id == :unclassified_compile  AND  WarningRatchet.high_signal_path?(row.file)
  high_signal_wae_paths/0 = adoption_test_files() ++ Path.wildcard("test/scoria/**/*_test.exs") ++ Path.wildcard("test/scoria_web/live/**/*_test.exs")
  These are COMPILE-TIME warnings emitted when test files are COMPILED — running the tests adds nothing the gate reads.

The fix (compile-only capture):
  Replace the `+ test` step's intent: still force-recompile lib/ AND compile all test files, but run ZERO tests.
  `mix test --only <a-tag-no-test-uses>` LOADS+COMPILES every test file (emitting compiler warnings to stderr)
  but runs only tests tagged with that tag — of which there are none — so it exits 0 having executed nothing.
  Keep MIX_ENV=test, keep stderr_to_stdout: true (compiler warnings go to stderr).
  Do NOT use --warnings-as-errors here: capture mode must run even when warnings exist (the gate classifies them downstream).
  Choose a tag that NO test in the suite uses (e.g. :__ratchet_compile_only__) — verify with grep before relying on it.

D-D2 critical-path computation (from 28-CONTEXT.md, load-bearing):
  critical path = SUM of stage maxima along  policy → build → max(test, ratchet, knowledge, connector, full-suite shards) → verify-summary
  using each job's (completedAt − startedAt) = ACTIVE run time (EXCLUDES queue time); slowest shard for matrix lanes.
  Run-level wall-clock headline = max(completedAt) − min(startedAt) across all jobs. NEVER sum billable minutes.
  Capture:  gh run view <RUN_ID> --json databaseId,headSha,createdAt,jobs,workflowName,url
  Per-job durations:  jq -r '.jobs[] | [.name, ((.completedAt|fromdateiso8601)-(.startedAt|fromdateiso8601))] | @tsv' | sort -t$'\t' -k2 -nr
