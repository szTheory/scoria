<objective>
Establish the shared trust vocabulary substrate and land TAINT-01 end-to-end: retrieved knowledge chunks carry a binary trust tier on `Knowledge.Chunk` metadata, defaulting fail-closed to `"untrusted"`.

This plan LEADS the phase with a tracer that proves the load-bearing contract every later leg (Envelope, Spotlight, Scan) depends on: the `Scoria.Trust` leaf vocabulary (D-01/D-02/D-03), the `Scoria.Trust.Tiered` protocol that keeps `Trust` a dependency-free leaf (D-23), and the `Source.metadata` → `Chunk.metadata` denormalization contract read with no join at retrieve (D-04). Expansion tasks then complete the host-override API (D-05) and the re-embed/re-index trust idempotency (D-04 red-team fix).

Purpose: All four requirement areas share ONE trust vocabulary and ONE fail-closed direction (unknown ⇒ untrusted). Proving that substrate first, wired through one real minting site, catches an architectural dead-end (compile cycle, wrong storage shape) after one commit instead of after every leg is built on it.

Output: `Scoria.Trust`, `Scoria.Trust.Tiered`, the `Chunk` protocol impl, the `Source` trust storage convention, and the `Knowledge` ingest/reembed/reindex/create_source/set_source_trust trust wiring.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| externally-sourced content → `Knowledge.Chunk` | ingested content is untrusted unless the host declares otherwise; the trust tag is the boundary marker |
| host `trust:` override → stored tier | a host-supplied string could mint a bogus-trusted row if not normalized |
| tenant A write → tenant B rows | a bulk trust update could leak across the tenant boundary |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-55-01 | Elevation of Privilege | `Trust.tier/1` reader | high | mitigate | Fail-closed default: absent/junk ⇒ `"untrusted"` (D-03); a forgetful/legacy row cannot read trusted. Proven by Task 1 tests. |
| T-55-02 | Tampering | `create_source`/`ingest_source` `trust:` opt | high | mitigate | All override values route through `Trust.normalize_tier/1` — a typo fails closed to untrusted + telemetry, never mints trusted (D-05). Task 2 test. |
| T-55-03 | Tampering / Information Disclosure | `set_source_trust/3` bulk UPDATE | high | mitigate | Bulk update WHERE double-scopes `source_id` AND `tenant_id`, mirroring the verified `knowledge.ex:70-75` pattern; cross-tenant isolation test in Task 2. |
| T-55-04 | Elevation of Privilege | `reembed_source`/`reindex_source` | medium | mitigate | Derive from stored `Source.metadata`, never a fresh default (D-04) — a re-embed cannot silently revert declared trust. Task 3 regression test. |
</threat_model>
