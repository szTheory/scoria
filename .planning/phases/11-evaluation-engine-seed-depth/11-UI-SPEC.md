# Phase 11 — UI Design Contract: Evaluation Engine + Seed Depth

> Visual and interaction contract for Phase 11. Generated by gsd-ui-researcher.
> Consumed by gsd-ui-checker, gsd-planner, gsd-executor, and gsd-ui-auditor.

Phase 11 is primarily **tooling and data infrastructure**: the `mix scoria.ui.shots` harness,
the 9-dimension critique rubric, `dev_seed.exs` depth, and a baseline audit. The only new
UI surface is the harness output format (CLI progress, per-screen JSON findings, gap-register
report). No new interactive dashboard screens are added in this phase; the existing dashboard
screens are the subjects of the harness, not changed by it.

## Spacing Scale

The project uses a 4px-base scale declared as `--scoria-space-{n}` tokens. The 8-point
grid is the enforced rule. All new surfaces in this phase must bind to these tokens.

| Token | Value | Usage |
|-------|-------|-------|
| `--scoria-space-1` | 4px | Icon gaps, badge internal padding, inline tight spacing |
| `--scoria-space-2` | 8px | Compact element spacing, button sm padding y |
| `--scoria-space-3` | 12px | Nav item padding, table cell padding |
| `--scoria-space-4` | 16px | Default element spacing, panel padding, button padding x |
| `--scoria-space-5` | 24px | Section padding, modal padding, pagehead margin-bottom |
| `--scoria-space-6` | 32px | Main content area padding |
| `--scoria-space-7` | 48px | Empty state vertical padding |
| `--scoria-space-8` | 64px | Major section breaks |
| `--scoria-space-9` | 96px | Page-level maximum breathing room |

Exceptions:
- Touch targets for interactive controls: minimum 44px tall (WCAG 2.5.5) — use padding to
  achieve this without breaking the token grid.
- The `mix scoria.ui.shots` CLI is a terminal tool; the spacing scale applies only to
  dashboard surfaces, not to shell stdout.

Source: `assets/css/02-tokens.css` §8.3.

## Typography

All sizes are token-bound. Components reference `--scoria-fs-*` and `--scoria-lh-*`.

| Role | Token | Size | Weight | Line Height | Font |
|------|-------|------|--------|-------------|------|
| Body | `--scoria-fs-body` | 14px | 400 (regular) | 1.5 (`--scoria-lh-body`) | IBM Plex Sans |
| Label / table header | `--scoria-fs-label` | 12px | 600 (semibold) | 1.5 | IBM Plex Sans |
| Panel heading | `--scoria-fs-panel` | 18px | 600 (semibold) | 1.2 (`--scoria-lh-tight`) | IBM Plex Sans |
| Page title / metric | `--scoria-fs-display` / `--scoria-fs-metric` | 30px | 600 (semibold) | 1.2 | IBM Plex Sans |
| Mono IDs / deltas | — | inherits `--scoria-fs-label` (12px) | 400 | 1.5 | JetBrains Mono |
| Badge / eyebrow | `--scoria-fs-badge` | 11px | 600 (semibold) | 1.6 | IBM Plex Sans |

**Exactly 2 weights in use:** 400 (regular) for body/prose, 600 (semibold) for headings,
labels, badges, and CTAs.

Source: `assets/css/02-tokens.css` §6, `assets/css/04-components.css`.

## Color

The design system uses semantic tokens only. Components never reference raw hex or raw
palette classes. The 60/30/10 split maps onto the token tiers.

| Role | Semantic Token | Dark Value | Light Value | Usage |
|------|---------------|------------|-------------|-------|
| Dominant (60%) | `--scoria-surface-app` | `#11100f` (basalt-950) | `#faf5ef` (ash-50) | Page/app background |
| Secondary (30%) | `--scoria-surface-panel` | `#181513` (basalt-900) | `#fff9f3` (white-hot) | Cards, sidebar, drawers, modals |
| Raised panel | `--scoria-surface-panel-raised` | `#211c19` (char-850) | `#ffffff` | Modal panels, raised cards |
| Accent (10%) | `--scoria-action` / `--scoria-ember-500` | `#e65a32` | `#b94f31` (scoria-600) | See reserved-for list below |
| Destructive | `--scoria-danger-action` | `#ff6b4a` (danger-dark) | `#9e2f20` (danger-light) | Destructive action buttons only |

**Accent (`--scoria-action`) reserved for:**
- Primary CTA buttons (`.scoria-button--primary`)
- Active nav item left-border indicator (`.scoria-nav[aria-current="page"]`)
- Focus ring (`--scoria-focus-ring: --scoria-molten-400`)
- Link color (`--scoria-link`)
- Brand tone badges (`.scoria-badge--brand`)
- Hover glow on task cards (`--scoria-glow-ember`)

**Not** used for body text, table rows, section labels, borders, or icons in their default state.

Status/tone colors are a separate semantic family (`--scoria-tone-{tone}-fg/bg/border`):
pass (green), info (teal), warn (amber), fail (red/orange), trace (purple), brand (ember).
These map to the `ScoriaWeb.UI.tone/1` function and `.scoria-badge--{tone}` classes.

Source: `assets/css/02-tokens.css`, `lib/scoria_web/ui.ex`.

## Interaction States Required by This Phase

Phase 11 captures every screen in a state matrix. The harness must be able to reach and
screenshot each combination. The following states must be representable:

| Dimension | States |
|-----------|--------|
| Data presence | empty (no records), populated (realistic dev_seed.exs data) |
| Overlay | baseline (no overlay), modal-open, drawer-open |
| Theme | dark (default), light (`data-theme="light"` on `.scoria-root`) |
| Viewport | desktop (≥1280px wide), mobile (375px wide) |

**Sentinel:** `data-scoria-ready="true"` on `<html>` — already set via `phx:page-loading-stop`
in `assets/js/scoria.js`. The harness gates every screenshot on this attribute before
capturing.

**State matrix:** 2 (data) × 3 (overlay) × 2 (theme) × 2 (viewport) = **24 combinations
per screen** (empty states do not have modal/drawer variants — the effective matrix is
(1×1 + 1×3) × 2 × 2 = **16 per screen**).

## 9-Dimension Rubric Contract

The critique rubric is the structured data contract for `EVAL-02`. Each per-screen findings
JSON must include exactly these 9 keys, each with a score (1–5) and a `findings` string array.

| Dimension | What it measures |
|-----------|-----------------|
| `brand_fit` | Warm basalt+ember palette, IBM Plex Sans, brand voice ("evidence over intuition") |
| `consistency` | Token-only classes, no raw palette leakage, shared components used correctly |
| `hierarchy` | Clear primary/secondary/tertiary visual weight; scannable without reading |
| `affordance` | Interactive elements look interactive; least-surprise behavior |
| `a11y` | Focus-visible on all controls, status not conveyed by color alone, WCAG AA contrast |
| `responsive` | Usable at 375px and 1280px without horizontal scroll or broken layouts |
| `motion` | Transform/opacity only, ≤200ms, no infinite loops, respects prefers-reduced-motion |
| `microcopy` | Headings, labels, CTAs, empty states, errors match the copywriting contract |
| `density` | Information per viewport area; not too sparse, not too cramped for the task |

Score semantics: 1 = critical violation, 2 = significant gap, 3 = acceptable, 4 = good,
5 = excellent. A screen with any score of 1 is flagged in the gap register as P0.

## Seed Depth Contract (EVAL-04)

`dev_seed.exs` must produce at least the following populated state for each screen:

| Screen | Minimum Populated State |
|--------|------------------------|
| Review Queue | ≥3 review candidates (mix of pending/approved/rejected), ≥1 with populated trace evidence |
| Incidents | ≥2 incidents (mix of open/resolved), ≥1 linked to a run |
| Eval Workbench | ≥2 eval specs, ≥1 with a completed eval run and score |
| Prompt Registry | ≥2 prompt versions, ≥1 with a release gate, ≥1 with a pending release |
| Approvals | ≥1 pending approval step with context |
| Connectors | ≥2 connectors (mix of online/degraded/offline) |
| Runs / Workflows | ≥4 runs (completed, in-progress, failed, pending-approval), ≥1 with full trace |
| Live Ops | Populated metrics from the above runs (non-zero counts) |
| Prompt Release Workbench | Navigable from Prompt Registry populated entry |

These minimums ensure the harness does not screenshot thin/empty states for screens that
are supposed to show data.

## Implementation Notes for Executor

1. **No new dashboard components.** Phase 11 adds `lib/mix/tasks/scoria.ui.shots.ex` and
   extends `priv/repo/dev_seed.exs`. It does not modify any LiveView template.

2. **Harness output location:** `priv/shots/{YYYY-MM-DD}/{screen}/{state}.png` and
   `priv/shots/{YYYY-MM-DD}/{screen}/{state}.json`. `priv/shots/` is `.gitignore`d except
   for `gap_register.md` and example contact sheets (committed per EVAL-03).

3. **Theme toggling in harness:** Set `document.querySelector('.scoria-root').dataset.theme`
   to `"light"` via JS evaluation between dark and light captures. The existing
   `ThemeToggle` JS hook already supports this.

4. **Viewport simulation:** The harness sets browser viewport to 1280×900 (desktop) and
   375×812 (mobile) between captures.

5. **Sentinel polling:** Poll `document.documentElement.getAttribute('data-scoria-ready')`
   with a 5000ms timeout and 100ms interval. Error copy is specified above.

6. **`flash_group` known issue (EVAL-02 will flag this):** `lib/scoria_web/ui.ex` line 195
   uses raw palette classes (`border-rose-200 bg-rose-50 text-rose-900` etc.) in
   `flash_tone_class/1`. This is a known DS-05 gap — the baseline audit will rank it.
   Do not fix it in Phase 11; document it in the gap register.
