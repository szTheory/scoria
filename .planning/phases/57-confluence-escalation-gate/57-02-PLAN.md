## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| host application environment → gate enforcement posture | Operator-controlled configuration determines whether the security control blocks |
| per-call `context` map → gate enforcement posture | Request-adjacent data may reach this map in a host that spreads request parameters into it |
| scanner verdict → evidence grade | A third-party or buggy scanner's output influences how strongly the gate enforces |

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |

| T-57-07 | Elevation of Privilege | `resolve_config/1` per-call rung | high | mitigate | Per-call `context[:confluence]` is tighten-only, so a host that spreads request parameters into the executor context cannot loosen enforcement from request data (D-33). Asserted by a test that attempts to loosen from context and expects the tighter value to survive. |
| T-57-08 | Spoofing | `grade/1` scanner evidence | high | mitigate | A malformed scanner tier that resolved through the junk-value fallback grades `scanner_infra` with reason code `:scanner_malformed`, never `declared`, so a buggy scanner cannot be presented to the ladder as positive evidence (D-30). |
| T-57-09 | Denial of Service | `validate_app_env/0` | high | mitigate | Never raises and is never called from `Application.start/2`; a typo logs once and falls back to that grade's shipped default rather than refusing every tool call or crashing the host at boot (D-34). |
