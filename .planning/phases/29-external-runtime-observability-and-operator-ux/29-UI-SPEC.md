| Secondary (30%) | #FFFFFF | Runtime rail cards, drawers, notebook cards, timeline evidence blocks |

Accent reserved for: the dashboard runtime row primary link, workflow/session reciprocal links, "View Session Evidence", selected compaction block anchor, and one current selection indicator. Do not use accent for every status chip or every card heading.

### Semantic State Colors

- `connected`: `#047857` text on pale emerald background.
- `offline`: `#B91C1C` text on pale rose background.
- `degraded`: `#B45309` text on pale amber background, only if backed by a real heartbeat/activity contract.
- `archived raw evidence`: neutral stone palette; raw evidence is truth, not danger.
- `derived summary`: sky or blue-tinted neutral panel to signal "interpreted memory" without implying replacement.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | View Session Evidence |
| Empty state heading | No External Runtimes Connected |
| Empty state body | External runtimes appear here when they attach through the MCP boundary. When a runtime links to a workflow session, open that session to inspect live presence and compacted memory evidence together. |
| Error state | Runtime observability data could not be loaded. Refresh the dashboard; if the problem persists, inspect the linked workflow run and presence projection for the same runtime instance. |
| Destructive confirmation | Disconnect Runtime: Disconnect this runtime from the current session? The live attachment will close, but workflow records, raw events, and compacted memory evidence will remain available for audit. |

### Copy Rules

- Status language must be factual and typed: `Connected`, `Offline`, and `Degraded` only when an explicit heartbeat contract exists.
- Offline notices must include the typed reason when available: `transport_closed`, `presence_left`, `session_not_found`, `heartbeat_timeout`, or `operator_disconnect`.
- Memory notebook copy must explicitly distinguish `Raw events` from `Compacted memory`; never imply the summary is the sole truth.
- Sequence-range labels lead the evidence language: `Events 120-164 compacted` rather than timestamp-first phrasing.
- Token labels must state what is counted: `Archived raw tokens` unless summary-token counts are separately persisted.

## Phase-Specific Visual Contract

- Keep the dashboard root as a scan-first embedded operator surface. Add the external runtime surface as a compact adjacent rail/card stack beside existing approval and connector posture sections, not as a new dominant fleet console.
- Preserve the existing Scoria visual language: stone background, white cards, subtle borders, shadow-light separation, and dense evidence grouped into readable blocks instead of flashy telemetry chrome.
- Runtime rows/cards must show, in this order: runtime identity, current status chip, linked session/run context, last seen or heartbeat age when available, and latest compaction freshness.
- The workflow/session page is the primary truth surface. It should gain a runtime context block above or beside the existing timeline, then a memory time-travel notebook below the timeline.
- The compaction view must use notebook blocks for `raw sequence range -> compacted memory`. Do not render a side-by-side text diff or patch-style comparison as the primary UI.
- Each compaction block must visually separate three layers:
  - range metadata
  - derived summary text
  - expandable raw evidence list
- Use calm emphasis. The only saturated focal points should be the selected runtime link, the selected compaction block, and destructive/offline warnings when a typed terminal reason exists.

## Component Inventory

- Runtime rail section on dashboard: compact card stack parallel to connector posture.
- Runtime row/card: runtime instance ID, tenant/actor label, transport kind, status chip, last seen label, linked session/run link, compaction freshness label, primary action.
- Runtime detail drawer or inline expansion: secondary operator facts such as first seen, last terminal reason, bounded runtime descriptors, and reciprocal workflow links.
- Workflow runtime context block: linked runtime identity, live presence state, session/run linkage, last seen, transport kind, and offline reason if present.
- Memory time-travel notebook: ordered compaction blocks anchored by `start_sequence` and `end_sequence`.
- Compaction block header: sequence range, compacted timestamp, archived event count, archived raw token count, and runtime snapshot link when available.
- Summary panel: summary text only, clearly labeled as derived memory.
- Raw evidence expander: lazy-loaded archived event list under a compaction block, default collapsed.
- Empty-state card: shown when a workflow has no compacted memory yet or no linked external runtime.

## Interaction Contract

- Dashboard runtime cards update in real time from Presence/PubSub projections, but they must not present Presence as durable truth. If the live state disappears, retain the durable identity and last terminal reason in the row/card presentation when available.
- The runtime rail supports one obvious primary action per row: navigate to the linked workflow/session when one exists. Secondary detail remains in a drawer or inline expansion.
- If a runtime has no linked workflow/session, the primary action changes to `View Runtime Context` and opens the compact detail drawer; do not navigate to an empty runtime-only full page by default.
- Runtime status chips behave as follows:
  - `Connected`: Presence entry exists and linkage resolves.
  - `Offline`: Presence left or transport closed; show typed reason when available.
  - `Degraded`: only if explicit heartbeat/activity evidence exists independent of transport keepalives.
- Workflow/session pages must show reciprocal navigation back to the runtime context card/anchor when a runtime link exists.
- Compaction notebook blocks are ordered by sequence range, oldest first, so operators can read session memory evolution chronologically.
- Raw evidence remains collapsed by default. Expanding raw evidence loads archived events lazily with explicit `Loading raw events...` and `Raw events could not be loaded` states.
- Clicking a compaction block anchor scrolls to and highlights that block; it must not open a modal for routine reading.
- Sequence-range links from runtime cards or offline notices should land on the exact compaction block when Scoria can resolve the latest compacted memory for that runtime/session.

## State Contract

- `No runtimes connected`: neutral empty card on the dashboard rail with the empty-state copy above.
- `Connected runtime`: emerald-toned status chip with linked session/run and freshness labels.
- `Offline runtime`: rose-toned status chip with last seen and typed reason when available.
- `Degraded runtime`: amber-toned status chip only if explicit heartbeat/activity data exists.
- `Linked session missing`: amber inline notice on a runtime row or workflow context block; reason label must be `session_not_found`.
- `No compacted memory yet`: neutral notebook card on workflow page explaining that raw events remain active and no archived block has been produced yet.
- `Compaction evidence ready`: notebook block renders range metadata, summary text, and raw evidence expander.
- `Raw evidence loading`: inline loading state within the block, never a page-level spinner.
- `Raw evidence failed`: inline failure state with retry action scoped to the block.

## Assumptions

- No dedicated runtime heartbeat contract exists in Phase 29, so `degraded` is specified but not expected to render unless implementation adds a real non-transport signal.
- The phase stays inside the existing `/scoria` dashboard and `/scoria/workflows/:id` truth path; no new primary runtime-only route is assumed.
- Token counts available from Phase 28 refer to archived raw tokens, not summary tokens, unless later schema changes prove otherwise.
