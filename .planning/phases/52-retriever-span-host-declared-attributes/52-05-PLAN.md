<objective>
Insert the shared `Semconv.merge_host_declared/2` stage into both adapter attribute pipes so host-declared keys ride the LLM (req_llm) and TOOL (jido) spans when present in metadata (D-ATTR01-5). This generalises the existing Jido `span_kind` host-override precedent to feature/route/archetype/intent.

Purpose: With host keys on every span type, the entire trace is sliceable by feature/route/archetype/intent (the SEED-012 JTBD). Caveat (D-ATTR01-7, verified): on a REAL `[:req_llm, :request, :stop]` emission, req_llm builds a fixed base map with no host-key channel, so this edit is correct/harmless for req_llm but only takes effect on hand-synthesized test events; the production carrier for host keys on the LLM/prompt lane is `emit_prompt_span/1` (52-03). The Jido adapter's metadata IS host-supplied at the call site, so `merge_host_declared/2` there is reachable in production.
Output: one added pipe stage in each adapter; adapter tests proving host-key pass-through (jido: production-shaped; req_llm: on its adapter test event, with the D-ATTR01-7 caveat documented).
