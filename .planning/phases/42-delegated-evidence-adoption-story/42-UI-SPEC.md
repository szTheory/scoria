### Type Rules

- Keep exactly two weights in this phase: `400` for narrative and metadata, `600` for headings, active labels, counters, and status chips.
- Use uppercase tracked labels only for section markers such as `Delegated Evidence`, `Projected Context Preview`, `Runtime Flow`, and typed status markers.
- Use monospace only for `run_id`, `step_id`, route fragments like `/scoria/workflows/:run_id`, delegated kind values, role IDs, and any typed reason code or field key.
- Keep long projected-context values in body text; do not render JSON walls as the default reading experience.

### Semantic State Colors

- `handoff recorded`: neutral stone badge; this is expected runtime truth, not success theater.
- `delegated child queued/running/completed`: reuse existing workflow status badge semantics from the tree.
- `projected context preview`: neutral stone well with blue only on explicit expansion or deep-link affordances.
- `adoption signpost`: blue text link or pill, never a large competing hero block.
- `support-truth warning`: amber notice when docs/source fragments drift or when a follow-up gap is explicitly deferred.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | Inspect Delegated Evidence |
| Empty state heading | No Delegated Handoffs Recorded |
| Empty state body | This run has no bounded delegated handoff yet. Start with the normal runtime flow, or inspect the workflow tree after `Scoria.start_handoff_run/3` records a handoff and child step under the same run. |
| Error state | Delegated evidence could not be loaded from the current run detail. Refresh the workflow page; if the problem persists, inspect the handoff row and child-step lineage through the same `run_id` before changing docs or examples. |
| Destructive confirmation | Defer remaining gap: Mark this adopter-facing rough edge as follow-up instead of current milestone scope? Keep the runtime-first adoption path unchanged and record the gap explicitly before closing the phase. |

### Copy Rules

- Teach one path first: `identity -> start -> inspect -> resume`.
- Refer to bounded handoffs as an `extension` or `delegation lane`, never as a separate onboarding path.
- Use `same durable run` consistently when describing lineage.
- Prefer `delegated role`, `delegated kind`, `handoff input`, and `projected context` exactly; do not swap in looser synonyms like `agent`, `task blob`, or `context dump`.
- Any preview helper copy must remind the reader that projected context is a bounded host-controlled slice, not broad runtime state.

## Layout and Interaction Contract

- Primary focal point on the main workflow screen: after the header establishes run identity and the tree/detail frame establishes topology, the run-level `Delegated Evidence` section becomes the main inspection anchor for this phase because it is the first place operators should confirm delegated lineage, bounded projected context, and same-run child execution without reconstructing truth from raw rows.
- Keep Phase 42 inside the existing `/scoria/workflows/:run_id` truth surface and the current docs/README surfaces. Do not create a separate delegated-work console or alternate onboarding page.
- Preserve the current desktop workflow layout:
  - header and status strip first
  - workflow tree and detail rail as the main two-column evidence frame
  - delegated evidence section inserted as a run-level section between the tree/detail frame and lower notebooks/timeline
- The workflow tree remains topology-first and compact. It may show the existing `handoff` marker and parent/child structure, but it must not become the full delegated-detail surface.
- The selected-step detail rail remains selected-step detail. It may reference delegated context when the selected step participates in a handoff, but it is not the primary delegated inspection surface.
- Add one dedicated run-level `Delegated Evidence` section that scans as calm summary-first cards before any expanded raw detail.
- Default card face for each delegated handoff must show, in this order:
  - root role -> delegated role
  - delegated kind
  - parent step -> child step lineage
  - current status
  - projected-context preview limited to 2-3 compact key/value rows
- Full `handoff_input`, full projected context, and optional adjunct metadata such as `capability_tags` sit behind progressive disclosure. Raw JSON is secondary, never first-read.
- If multiple delegated handoffs exist in one run, cards sort by workflow sequence ascending so the delegation chain reads in execution order.

## Component Inventory

- Delegated evidence section shell: run-level section with short explanatory subcopy and card stack.
- Delegated evidence summary card: one card per delegated handoff projection, using the curated DTO rather than raw workflow joins.
- Lineage row: parent step ID, child step ID, and same-run confirmation.
- Role path row: root role -> delegated role with delegated kind chip.
- Status row: handoff status plus child-step status using existing workflow badge semantics.
- Projected context preview: compact 2-3 row preview with truncation and `View full context` disclosure trigger.
- Handoff input disclosure: collapsed-by-default body showing the persisted work brief in grouped rows.
- Projected context disclosure: collapsed-by-default body showing the full bounded context slice with stable key ordering.
- Optional metadata disclosure: only render adjunct metadata like `capability_tags` when durable truth exists; frame it as secondary host-supplied hints.
- Adoption signpost callout in docs/README: small inline branch from the runtime-first story pointing to `Scoria.start_handoff_run/3` and `/scoria/workflows/:run_id`.
- Gap ledger note: compact amber callout for any explicitly deferred adopter-facing rough edge.

## Interaction Contract

- Clicking a workflow tree row continues to update the right rail only; it must not steal focus from the run-level delegated evidence section.
- Clicking `Inspect Delegated Evidence` from a header strip or docs deep link should scroll or jump to the run-level delegated evidence section on the same workflow page.
- Disclosure behavior is progressive and low-noise:
  - default all cards collapsed to summary state
  - allow one expanded full-context disclosure per card without leaving the page
  - preserve expanded/collapsed state during step selection changes when possible
- The delegated evidence section must read from one curated delegated projection object if available; raw `handoffs`, `steps`, `checkpoints`, and `events` remain secondary evidence beneath that projection.
- Projected-context preview truncates long values and hides nested structures behind disclosure. Never dump entire nested maps inline in the summary card.
- If a delegated handoff exists but the child step is not yet available, show an explicit `child step pending` state instead of leaving lineage blank.
- If a run has no delegated handoffs, render the empty-state card in the delegated evidence section and keep the rest of the workflow page unchanged.
- Docs and README should link bounded handoffs from the runtime-first flow after `start` and `inspect`, not before `Scoria.start_run/2`.
- Checked source fragments must reflect the same order of explanation used in docs: identity first, start second, inspect via `run_id`, then branch to bounded handoffs as an advanced extension.

## Docs and Adoption Contract

- README `Quickstart` remains the primary first-read adoption path and continues to demonstrate `Scoria.start_run/2`, `Scoria.get_run/1`, `Scoria.list_runs_for_session/1`, `Scoria.resume_run/2`, and `/scoria/workflows/:run_id` before any handoff branch.
- README `Bounded Handoffs` remains discoverable but should read as a narrow branch from that primary flow, not a parallel product entrypoint.
- `docs/phoenix_runtime_example.md` remains the canonical runtime-first walkthrough. Any handoff mention there should be a short signpost, not a full second tutorial.
- `docs/bounded_handoffs.md` remains the deep dive and must explicitly promise inspectability through `Scoria.get_run_detail/1` and `/scoria/workflows/:run_id`.
- Checked fragments in `test/support/scoria/adoption_example.ex` should include both the runtime-first path and the delegated-handoff branch, but the runtime-first path remains first in narrative order.
- Any remaining rough edge must be labeled either `current milestone closeout` or `deferred follow-up`; do not leave handoff guidance ambiguous.

## State Contract

- `No delegated handoffs`: show the empty-state card with runtime-first guidance and no extra warnings.
- `Delegated evidence ready`: show one or more summary cards with root role, delegated role, kind, lineage, status, and projected-context preview.
- `Summary expanded`: reveal grouped `handoff_input` and full projected context without navigating away.
- `Child step pending`: show neutral status helper copy that the handoff is recorded but delegated execution has not yet produced a child-step readback.
- `Projection incomplete`: show amber helper copy if lower-level truth exists but the curated delegated projection is missing required fields; keep raw evidence link visible.
- `Evidence load failed`: show the error-state card above the section; preserve the rest of the workflow surface.
- `Docs drift identified`: show an amber callout in planning/support artifacts, not a dramatic UI error treatment in the operator page.
- `Gap deferred`: show a compact amber note with explicit reason and destination phase/follow-up reference if known.

## Assumptions

- This phase extends the existing workflow run screen and adoption docs rather than creating a new route family or a notebook-style delegated workstation.
- The repo continues to use Phoenix LiveView and repo-local Tailwind utility classes already visible in `WorkflowLive.Show` and related components.
- A thin delegated projection will be added to the run-detail DTO or equivalent curated public read model, while raw evidence arrays remain available underneath.
- No third-party component registry, icon package, or JS-heavy disclosure widget is required for this phase.
