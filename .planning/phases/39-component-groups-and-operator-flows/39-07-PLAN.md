## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| ?approval=<id> URL → drawer | An operator-supplied approval id opens a drawer; must respect tenant/visibility scoping |
| audit event → displayed attribution | Decider/time provenance is read from the audit outbox for display |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-39-07-I | Information Disclosure | ?approval=<id> deep-link | high | mitigate | The drawer loads the approval through the same tenant-scoped projection/lineage path as the inbox (list_decided_approvals/1 + existing scoping) so a deep-link cannot open an approval outside the operator's scope; handle_params resolves the id against the scoped set only |
| T-39-07-R | Repudiation | fabricated/incorrect attribution | high | mitigate | Decided-at/decider sourced from the append-only decision AuditOutboxEvent (inserted_at/actor_ref), not updated_at or the requesting actor; missing event → "time unavailable", never invented (D-20) |
| T-39-07-Sp | Spoofing | receipt implying success/reversal | high | mitigate | D-27 receipt states the recorded decision only + run link; D-19 positive-predicate gate removes all reversal affordances in Decided scope |
| T-39-07-T | Tampering | fabricated expired history | high | mitigate | Expired renders no fabricated time/actor absent a real approval.expired audit event (D-18/D-21) |
| T-39-07-SC | Tampering | dependency installs | low | accept | No package installs this phase |
</threat_model>
