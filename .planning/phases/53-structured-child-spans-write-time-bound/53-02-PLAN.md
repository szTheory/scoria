<objective>
Build the closed key registry that makes SEC-01 structural rather than procedural. `Scoria.Observe.Semconv` already owns every key string Scoria writes (`openinference.span.kind`, `scoria.retrieval.*`, `scoria.prompt.context`, the four host-declared keys); this plan makes it own the *admission decision* too: a `%{key => class}` registry whose class vocabulary has no representation for arbitrary prose (D-06b). It also adds the guardrail vocabulary (D-05f) and the type-only error projection (D-06g) that plans 53-03 and 53-07 consume.

Purpose: the guarantee behind phase SC#4 — "a regression test goes RED if a future developer introduces an unbounded free-text attribute" — lives here, not in `Bounds`. `Bounds` (plan 53-04) is the enforcement point; this is the source of truth it enforces against. Phase 54's DOCS-02 conformance check will read the same registry.
Output: `attribute_registry/0`, `attribute_classes/0`, `vendor_key_prefixes/0`, `denied_exact_keys/0`, `denied_key_segments/0`, `bounds_marker_keys/0`, the three guardrail enums + `guardrail_attributes/1` + `normalize_reason_code/1`, and `error_attributes/1` — plus the canary tests that lock them.
</objective>

A caller cannot smuggle an extra key through it, because it does not read extra keys.

Type-only error attributes** (D-06g). `error_attributes/1` accepts an exception struct (or a `{kind, reason}` from a `catch`) and returns exactly two keys — `"exception.type"` and `"error.type"` — both set to the exception's module name (via `inspect(e.__struct__)` for a struct; a stable atom-derived label for a throw/exit). It never reads `Exception.message/1`, never touches `__STACKTRACE__`. An exception message is arbitrary-length, attacker- and prompt-influenced text: `Ecto.NoResultsError` embeds the query, `Postgrex.Error` embeds parameter values, and `Scoria.MCP.Executor` already stuffs a raw failure term into its tool telemetry. A module name is low-cardinality and enum-like; that is the whole capture surface. Document in the moduledoc that this deliberately inverts OpenInference's capture-by-default posture (`OPENINFERENCE_HIDE_INPUTS`/`HIDE_OUTPUTS` default to False) — Scoria mirrors the vocabulary and inverts the default. A `capture_error_messages` config key may exist as a documented future opt-in but is NOT implemented in this plan.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Scoria developer -> `attribute_registry/0` | The only path by which a NEW Scoria-owned attribute key can become persistable. The canary test is the tollbooth. |
