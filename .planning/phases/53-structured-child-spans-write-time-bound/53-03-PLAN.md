<objective>
Build the single span primitive every producer in this phase funnels through: `Scoria.Observe.span(kind, name, opts, fun)` — a transparent wrapper that owns duration measurement, failure-status marking, and the emit, and that reraises the host's exception unchanged (D-01a, D-01d). Then refactor Phase 52's two emitters onto it with zero contract change (D-01c), and add the `tenant_id` double-write (D-00c/D-01e) without which every span this phase produces is invisible to the operator.

This formally revises Phase-52 D-R6 ("success-path only"): EVENT-01 says spans are duration-AND-failure-bearing. Failure-bearing IS the job to be done — the SWE opens the trace tree *because something went wrong*. The infrastructure is already built and orphaned: `assets/css/04-components.css:1100-1119` ships a WCAG-compliant errored-span overlay that no component applies, and `lib/scoria/eval/online_scoring.ex:453` already matches `String.upcase(status_code) == "ERROR"` to drive negative-signal sampling — the eval flywheel is waiting on ERROR spans that nothing emits.

Purpose: phase SC#3, and the seam plans 53-05, 53-07, and 53-08 all depend on.
Output: `span/4`, `with_tool/3`, `with_prompt/3`, `with_guardrail/3`, `trace_id_for_run/1`, a shared private span-map builder, and `test/scoria/observe/span_test.exs`.
</objective>

    Extend `Scoria.Observe`.

    **`span(kind, name, opts, fun)`** — the single primitive.
    - Mints a fresh own `span_id` (`opts[:span_id] || Ecto.UUID.generate()`). Own-id semantics (Phase 52 D-R2): `:id` is always THIS span's fresh id, never a caller's existing id (that would PK-collide — the span `insert_all` has no `on_conflict` and the row is silently dropped).
    - `start_wall = DateTime.utc_now()`, `start_mono = System.monotonic_time()`. Duration is computed from the monotonic clock; `end_time` is `DateTime.add(start_wall, elapsed)` so `end_time - start_time` is a real, monotonic-derived interval rather than two back-to-back wall reads.
    - Runs `fun.()` inside a `try`. Each outcome branch does its own single emit and then returns or reraises. **There is no emit call reachable after the `try` block** — that is the double-emit footgun (RESEARCH Pitfall 1) and Test 5 exists to catch it.
      - `rescue e` -> emit with `status_code: "ERROR"` and `Semconv.error_attributes(e)` merged into attributes, then `reraise e, __STACKTRACE__`.
      - `catch kind_c, reason` -> emit with `status_code: "ERROR"` and type-only error attributes, then `:erlang.raise(kind_c, reason, __STACKTRACE__)`. (`reraise/2` covers only the `rescue` case; a `throw`/`exit` needs the BIF.)
      - `else value` (or the normal `try` result) -> emit with `status_code: "OK"`, return `value` verbatim.
    - `__STACKTRACE__` is only bound inside the matching clause — this is exactly WHY the reraise must live inside the branch, and why the naive "add a branch, keep the shared emit" refactor produces two rows.
    - The emit itself stays wrapped `try/rescue -> :ok` (Phase 52 D-R6 continuity — a raising telemetry handler can never reach the caller). Note the asymmetry and document it: the EMIT is swallowed; the HOST'S exception is not. `span/4` is transparent to the caller's failure and opaque to its own.
    - `opts` keys: `:trace_id`, `:parent_id`, `:span_id`, `:tenant_id`, `:workflow_run_id`, `:session_id`, `:attributes` (a pre-built map merged into the span's attributes), plus the four `Semconv.host_declared_keys/0`.

    **Moduledoc citation (D-01d requires this explicitly):** state that `:telemetry.span/3` (hexdocs.pm/telemetry) already implements this catch-mark-reraise contract — "if an exception does occur, an `EventPrefix ++ [exception]` event will be emitted and the caught error will be re-raised" — so this shape is the ecosystem-standard idiom, not a Scoria invention. Scoria does not call it directly only because every existing consumer (`Telemetry.handle_event/4`, `Buffer`, `ReviewerBroadcast`) is wired to a single flat `[:scoria, :observe, :span, :stop]` event rather than telemetry's three-event start/stop/exception shape. Also state that OpenTelemetry's own `with_span/3` is `try...after` — it does NOT catch, does NOT set an error status, and records no exception; Scoria's `try/rescue -> ERROR + reraise` is strictly stronger than the reference implementation.

    **Moduledoc deferral note (D-02b):** `parent_id`/`trace_id`/`span_id` are ALWAYS explicit opts. An implicit process-local context variant was designed and deliberately cut — not one of this phase's producers (a pre-run release gate, the workflow runtime, two Oban job processes) runs in a process where an ambient span context would resolve correctly. State this as a known, deliberate deferral so a future reader does not mistake it for an oversight.

    **`tenant_id` double-write (D-00c/D-01e).** The shared span-map builder MUST write `tenant_id` BOTH as a top-level span field AND into `attributes["tenant_id"]`. `ReviewerBroadcast.span_stopped/1` fail-closes on a missing top-level `tenant_id` (returns `:dropped`), and `OrchestratorLive.build_hydrated_trace/2` SQL-filters on `attributes->>'tenant_id'` — a span that sets only one of the two is either un-broadcast or un-hydratable. Do the same for `workflow_run_id` and `session_id`, which `@span_buffer_fields` also excludes from the top-level whitelist (Phase 52 D-00: all keys go in `attributes`).

    **Thin kind wrappers (D-01b):** `with_tool(name, opts, fun)`, `with_prompt(name, opts, fun)`, `with_guardrail(name, opts, fun)` — each delegates to `span/4` with its kind. No `with_agent/3` (no success criterion, no producer).

    **`trace_id_for_run/1` (D-03a):** accepts a `%Scoria.Workflows.Run{}` or a run id binary and returns the run id. A RUN IS A TRACE. Document why this is safe: `ai_spans.trace_id` FKs to `ai_traces`, `Buffer` upserts trace rows idempotently (`on_conflict: :nothing`), and `ai_traces.id` has no other producer — so reusing `run.id` is FK-safe and collision-free, and it creates the run↔trace join the operator surface already assumes (`OrchestratorLive` renders `trace[:workflow_run_id]`). Before this, both adapters did `metadata[:trace_id] || Ecto.UUID.generate()` — a fresh random orphan trace per span.

Extract the shared attribute pipeline (currently duplicated at `observe.ex:73-77` and `:138-143`) into ONE private builder both call — single origin, per the D-00c doctrine. Both now also pass `tenant_id`/`workflow_run_id`/`session_id` through the double-write. Deprecate nothing: an `@deprecated` on a helper shipped one phase ago is churn. This fulfills Phase 52's D-ATTR02-1 promise ("the identical Semconv keys relocate onto a real PROMPT child span with zero contract change") literally.
