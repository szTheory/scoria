<objective>
Build the one choke point every attribute payload passes through: `Scoria.Observe.Bounds.enforce(metadata, :span | :event)`, called in `Telemetry.handle_event/4` between `Redactor.redact/1` and the two sinks (D-06a). It enforces the closed key registry plan 53-02 built, plus size/count/depth caps, and it fails closed.

The guarantee is the registry, not the size cap. A size bound alone does not stop raw text — a 200-byte completion fits any cap. Only closing the key space is structural (D-06b). This is the enforcement point for that closure, placed where no future adapter can bypass it: not in `Redactor` (whose `:mfa` hook is adopter-removable, `redactor.ex:11-14`), not in the Semconv builders (trivially bypassed by the next adapter that builds attributes inline), and not at the DB layer (`Buffer` uses `insert_all`, which bypasses changesets entirely, `buffer.ex:129`).

Bounding BEFORE the broadcast is load-bearing: a 2 MB attribute map pushed to an open operator LiveView is a real browser DoS.

Purpose: phase SC#4, and SEC-01 end to end.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| any span emitter -> `Telemetry.handle_event/4` | The single point where every attribute payload — Scoria's own, an adapter's, a host's — becomes durable and/or broadcast. This is THE trust boundary of SEC-01. |
| `req_llm` upstream -> `merge_req_llm_attributes/2` -> `Bounds` | An unfiltered `Map.merge` of a dependency's output. `Bounds` is the last line. |
| adopter config (`Redactor`'s `:mfa` hook) -> `Bounds` | An adopter can replace redaction wholesale. They cannot remove `Bounds`. |
| `Bounds` -> `ReviewerBroadcast` -> operator's browser | An unbounded payload here is a client-side DoS, not just a storage problem. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-53-01 | Information Disclosure | `Bounds.enforce/2` key admission | critical | mitigate | Closed-registry positive allowlist (ASVS V5). Unregistered key -> DROP, never truncate.
