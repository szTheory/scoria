<objective>
Make guardrails first-class. A guardrail is a **policy decision point** that Scoria evaluates on the runtime path of an AI step, whose outcome can **allow**, **block**, or **escalate** that step to a human (D-05a). This is not invented vocabulary — it describes code that already exists, using verbs already in the source (`ReleaseGate.check/1`, `Verdict.blocks_release?/1`).

The differentiator is worth stating plainly: **every peer models the *check*; almost none model the *decision*.** OpenInference has a `GUARDRAIL` span kind with zero outcome attributes. Langfuse has a `GUARDRAIL` observation type with no effect field. OTel explicitly *rejected* a GenAI policy vocabulary and routed it to a generic namespace that still has no outcome field. The missing primitive across the whole ecosystem is `effect` — and XACML has had it since 2013. `scoria.guardrail.decision` is that primitive.

The security rule is the load-bearing one. **There is no free-text `reason` key** (D-05g). The unbounded reason string is the leak nobody guards: every masking layer in the ecosystem targets model inputs and outputs, and none catches a guardrail's own free-text explanation — which is generated *by a model that just read the PII* and routinely quotes it verbatim. Scoria has that exact string one refactor away from the trace store (`Scoria.Eval.JudgeRunner` produces a free-form `explanation:` at `judge_runner.ex:167` and `:202`), and the OTel-blessed key name actively invites putting it on a span. Someone will. The fixed-key projector built in plan 53-02 is what stops them — structurally, not by review convention.

Purpose: SC#1's `guardrail` leg, and the SEC-01 rule with the sharpest teeth.
Output: `lib/scoria/observe/guardrail.ex`, G1 wired at `Scoria.Runtime.start_run/2`, and `test/scoria/observe/guardrail_test.exs`.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| caller's outcome map -> `Guardrail.emit/1` | A developer wiring a new gate — or refactoring an existing one — can pass anything here, including an LLM-generated explanation. `Scoria.Eval.JudgeRunner`'s free-form `explanation:` (`judge_runner.ex:167`, `:202`) is one refactor away from this seam. |
| `Guardrail.emit/1` -> persisted span attributes | Guardrail spans are the most sensitive spans in the system: a guardrail fires precisely *because* something in the payload was problematic, so its own explanation is disproportionately likely to quote the problematic content verbatim. |
| `Guardrail.emit/1` -> host's run lifecycle | An emit that raises must not fail a host's run. |
